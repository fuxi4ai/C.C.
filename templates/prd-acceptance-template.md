> 2. **文件位置**:`~/Documents/Claude/brain/logs/checkpoints/{YYYY-MM-DD}_{任务简称}_PRD.md`
> 3. **PRD checkbox 合同**:实施者只能填 `[?]` 已达成+证据 / `[!]` 未达成+原因 / `[~]` 不确定+判断点。`[✓]` 由 **Doctor 或 Doctor 明确指定、且未参与实施的独立验收方**落。客观 TODO 证据代勾属常驻授权、**仅限 PRD 外的普通 TODO**（G-X136 补钉），不占 PRD checkbox
> 4. **验收主体 = 功能/需求**:每条标准描述用户可感知的行为、结果或质量约束；文件、Grep、脚本输出只是证据。每项必须**可复核**（机器比对或预先定义的人工验收方法）。**不写"做好了"/"完整"/"修复了"** 等主观陈述 — **写了等于没写**
> 5. **双向闭环关闭**:全 ✓ 或 Doctor 显式取消(原因+时间)= 两种合法关闭。**禁止 CC 自动关闭**
> 6. 详见:`brain/permanent/通用教训.md` G-X4 + `brain/references/PRD交付标准主机制_设计提案.md`

## §二 · 交付标准(Acceptance Criteria · 验收主体＝功能/需求)

> ⚠️ **实施者填写规则**:
> - `[ ]` = 默认未开始 · 实施者不能直接改 `[✓]`
> - `[?]` = 实施者认为已达成 · **必带证据**(可重放：测试输出 / 人工验收记录 / 截图与判定依据等)
> - `[!]` = 实施者未达成 · **必带原因**
> - `[~]` = 实施者不确定 · **必写需验收方判断的具体点**
> - `[✓]` = **只由 Doctor 或 Doctor 明确指定、且未参与实施的独立验收方落** · 实施者看到自己即将打 `[✓]` → 立即停 + 改 `[?]`
> - 没证据 = 等于没填(回退到 `[ ]`)
> - 每项带追踪字段：`requirement_id → 预期行为/结果 → 验收方法 → 证据 → 状态`；「每项必须可复核」——视觉/交互/主观质量需求可用**预先定义的人工验收方法**

> **分轨验收(2026-08-14 Doctor 裁「A 分轨」· 阶段 2.5)**:
> - **客观轨** = 机器可判事实——实施者填 `[?]`+证据,独立审查员背书(必附验证动作记录:重跑命令/实跑输出),**Doctor 或指定独立验收方签一个总 ✓**。
> - **原则轨** = 结论/裁定类(结论认不认 / 判定接不接受 / 建议采不采纳 / 处置方式)——**验收方逐条 ✓**。**只收开发完成后首现的验收裁定**；开发中 Doctor 已拍板的分叉裁定不列原则轨(变更记录留痕即止 · 2026-08-15 Doctor 立)。
> - 「指定独立验收方」**必须由 Doctor 指定**；独立审查员默认只有背书权，不自动取得 `[✓]` 权。
> - 一票否决 + 抽查权保留;抽查发现背书失实 → 该场客观轨 ✓ **全部回退**。
> - ✓ 的裁定权始终在 Doctor 或指定独立验收方(实施者身份看本轮角色、不看模型身份);转录对话裁定落盘时,须在签核行注明原话与时间(例:「✓ 系 Doctor 2026-08-14『都可以勾』· CC 转录」)。

## §四 · 状态（单一生命周期 · 2026-08-18 十轮合同）

> 生命周期：`draft → in_progress ↔ blocked → awaiting_acceptance → delivered | cancelled`。一次只能在一个状态 · 状态变更必须有时间戳。任务授权、实施者、独立审查员、验收签字权、决策归属分别记录，不混为一人或一份授权。

- [ ] draft（立卷时 · 授权核实中或未决 · 时间: ____）
- [ ] in_progress（任务已授权且无阻断性歧义 · 直接实施 · 时间: ____）
- [ ] blocked（存在阻断性歧义 · 暂停对应实施等 Doctor 裁定 · 时间: ____）
- [ ] awaiting_acceptance（实施者已对所有交付标准填三态 · 时间: ____）
- [ ] delivered（Doctor 或指定独立验收方已把所有 `[?]` 转为 `[✓]` · 时间: ____）
- [ ] cancelled（Doctor 显式取消 · 时间: ____ · 原因: ____）

**关闭路径**(回顾铁律):
- ✓ 全 ✓ 关闭:所有交付标准由 Doctor 或指定独立验收方打 ✓

## §七 · 模板使用规范(给 CC)

### 立 PRD 时
1. 任务已获执行授权且无阻断性歧义 → **直接立卷**（不主动问「是否同意立 PRD」）；授权无法核实（state: unverified）→ 停在 draft，先核实授权
2. 复制本模板到 `~/Documents/Claude/brain/logs/checkpoints/{date}_{name}_PRD.md`
3. 填 §一(目标 + Doctor 原话 + 规模估算)+ §二(交付标准 · 验收主体＝功能/需求)+ §2.5(执行清单)+ §三(非交付项)+ frontmatter 授权字段
4. 实施者**不能填 §二 的 `[ ]` 之外的状态** · 等开始执行后才能改

### 任务执行中
- 每达成一条交付标准 → 立即改 `[ ]` → `[?]` + 填证据(不要等任务结束一次填)
- 中途发现某条达不到 → 改 `[!]` + 原因 + 提 Doctor
- 中途发现某条不确定 → 改 `[~]` + 列出验收方需判断的具体点
- 出现阻断性歧义 → §四 改 blocked，open_decisions 登记（事项/是否阻断/决策归属/状态），就该分歧请 Doctor 裁定；非阻断问题继续工作
- 任务范围扩大 → 不要私自加交付标准 → 请 Doctor 裁定 + 改 §一

### 任务结束时
1. 所有交付标准都填了三态之一 → 把 §四 状态从"in_progress"改为"awaiting_acceptance"+ 时间
2. 触发 /save → 在 brain-save 回报里贴 PRD 文件路径 + 状态
3. 等 Doctor 或指定独立验收方验收
4. **不能在 §四 自打"delivered"**

### 任务取消时(Doctor 操作)
- Doctor 写"取消"+ 原因 → §四 状态"cancelled"+ 时间 + 原因
- CC 触发 /save 记录未完成项
