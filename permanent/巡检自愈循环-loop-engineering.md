# 巡检自愈循环 · Loop Engineering 设计

> 状态：**draft v2 · 独立对抗审查后修订 · 待 Doctor 批准实施**（实施者不自签）。
> 依据＝全局 Settings「持续修复与交付闭环」条（08-29 V.V. 吸收版）+ 实施与验收分权 + 风险分级 + 授权不扩张 + 证据必须可重放。
> 审查记录：2026-08-29 独立 subagent 对抗审查（未参与起草）→ **PASS_WITH_LIMITS**：架构不推翻，四条 🔴 已全部吸收进 v2（F3 备份路径收敛 / 清零核验域补全 / F1 触发器析取式 / 批准换文）。审查报告仅作背书证据，不构成验收落签。
> 本设计针对 [[定时任务巡检机制]] 第九节那个悖论的第二叉：「巡检器一旦获得写权限，它自己就成了需要被巡检的东西」——在**规避全部历史失败模式**的前提下，把「只报告不动手」升级为**分梯级的自愈循环**。

## 0 · 背景：为什么「只报告不动手」是当时的最优解

2026-08-02 立规时，「修」的风险来自当时已知的失败族，每一条都有编号（全文见 [[通用教训]]）：

1. **认知失真**——08-01 一天内 CC 关于定时任务的结论被推翻三次，全是从旧日志拼出来的（拼日志=读到的不是现在）；照错认知去修，修的就是错的地方。
2. **静默成功**（G-X118）——07-31 改了 SKILL.md，diff 可见、无报错，但调度器读的是另一棵树；「工具能写到哪，压过了任务该落到哪」。
3. **修一个真原因、漏三个**（G-X141 活例）——07-31 待办「补挂载探测段」把一个原因腌成单一结论；照做会漏「挂载盘写不进」这个沉默失败，修完看起来还像修好了。
4. **一字之差改坏生产**（08-02 决策「zhuzhao 改动交 Doctor 终端做」）——92 行密集整体替换，sha 只能验对错、不告诉错在哪个字。
5. **记成功≠真成功**（G-X51）——无人值守班卡死悬挂，零日志零产物，调度器却记 lastRun 成功。
6. **正常路径绿≠失败路径对**（G-X150）——fail-fast 三轮验收每轮在正路上过、负路上被证伪。
7. **修一处漏一处**（G-X111 追记）——巡检脚本两个函数各写一遍过滤逻辑，修 bug 只改了一处，RED 误报差点让刚建立的告警机制第一次验证就自我否定。
8. **误报毁告警**（G-X122）——告警的价值由它沉默的时候保证；一条 RED 误报就能让真信号从此没人看。
9. **贴出的命令=已启动的开关**（NOTE-20260728-001）——命令一经贴出就当已执行，时序靠磁盘证据不靠记忆。
10. **占位符事故**（G-X134）——命令块部分失效部分照跑，失败被后续成功输出淹没。
11. **规则修订双轨并存**（G-X151）——追加订正、上游旧文未替换，执行侧面对两套现行命令。
12. **选择器 glob 拾取治理资产**（G-X162）——「文件存在+日期新」被当成「已授权消费」，绕过治理链。
13. **实施者自签**（RISK-20260817-002 / G-X4）——「宣称完成未核」多轮复发，自然语言「PASS/闭环」同属验收动作。

「只报告不动手」一次性地规避了全部 13 条——代价是修复永远等 Doctor。本设计的目标：**在保留全部 13 道门的前提下，把其中「机器可证、射程限定、可回退」的那部分修复还给循环**。

## 1 · 悖论的工程化解法

悖论两叉，分别处理：

- **叉一「坏了谁发现」**：已解（周班自证 + /resume 兜底两层），本设计不动。
- **叉二「有写权就变成需要被巡检的东西」**：不靠「禁止写」解，靠三条**同时成立**的约束解：

> **(a) 写权受限**：只允许执行 §2 预注册白名单内的修复动作，且只碰「巡检机制自己」的资产。**技术性强制靠「授权调用形态」**——白名单里每个动作写明可用的工具与参数形状（如 F3 只允许 `update_scheduled_task` 且只传 description 参数、taskId 必须 exact-pin 字面值），§5 负向测试把越权形态做成非零拒绝；白名单之外一律 fail-closed 回「只报告」。诚实口径：射程＝调用形态收敛＋事后留痕，不是结构保证——留痕即 (b)。
>
> **(b) 写必留痕**：每次修复动作写一行 append-only audit log（`brain/permanent/_repair_audit.md`，schema 见 §2 审计层），含时间戳/触发证据/动作/回退点/验收判据/实施者/状态。audit 经 Doctor commit 后于 git diff 显形；**读侧以文件本体为准，不依赖 git**。
>
> **(c) 留痕必被读——且读有双通道，不与叉一同死**：① 人读通道＝brain-resume Step 0.6 升级为「先读诊断卡+audit 尾段，再报新鲜度」；② **机器读通道＝周班 prompt 增一步：读 audit 尾段，存在 🔄 未验行则列入异常清单附报（走 exit 1 通道，不破坏「正常零输出」契约）**——周班存活期间每周一次机器阅读，叉二不挂在叉一唯一的脆弱点上。

⇒ 修复器的写权不再是隐形权力，而是「每写必留痕、留痕必被双通道读」。**验收判据优先写成「下一次运行自证」的谓词**（见 §2 L3）——对 F1 天然收敛：修复失败 ⇒ 快照继续过期 ⇒ 触发条件再度成立，**检测即验收**，不需要任何人读 audit 来判对错。

## 2 · 分层结构（L0–L3 + 审计层）

### L0 · 诊断（永远允许 · 只读 · 先于一切修复）

- 探针集（全部只读）：`list_scheduled_tasks`（本壳可读 Gateway store 元数据）· 快照 `generated_at` · gitcheck · **G-X51 取证法**（`list_sessions` + `read_transcript` 查班死因）· launchd/crontab 由 Doctor 侧跑（命令贴出，不代跑）。
- 每次诊断落「诊断卡」（模板 `brain/permanent/巡检诊断卡模板.md`，append-only，时间戳+证据指针+未确诊项清单）。诊断卡须粘贴探针**原始输出块**（如 list_scheduled_tasks 返回、快照摘录），禁转述——证据必须可重放。
- **死因未确诊，不进 L2**——G-X141「修一个真原因漏三个」的硬门。诊断卡的判语只能是「确诊/未确诊」，不许写「疑似即修」。

### L1 · 自愈（白名单 · 幂等 · 可回退）

| 编号 | 动作 | 射程 | 触发 |
|---|---|---|---|
| S1 | 快照刷新：贴一条 Doctor 终端命令重跑 `scheduler_snapshot.py`（沙箱读不到 live 树，此步**永远**走 Doctor 终端——把自主边界标清楚） | 快照两文件（脚本自身只读保证） | 快照超期 |
| S2 | 新鲜度判据修正：快照 `_meta` 加 `triggered_by`（scheduled/manual）字段，脚本侧一行改动——根治 08-02 实测「手动跑冒充周班在跑」的双向假绿灯 | scheduler_snapshot.py 一行 | 方案批准后一次性实施 |
| S3 | 周班 prompt 加「快照写后自证」步：跑完脚本必须回读 `generated_at` 比对，不前进即报 🔴 | 周班 prompt 一个步骤段 | 方案批准后一次性实施 · **走 Doctor 终端 SHA 往返**（见 F3p） |

### L2 · 修复（预注册失败模式表 · 字段级最小 diff · 写后回读）

| 失败模式 | 触发证据（硬） | 修复动作 | 验收判据（机器可验） | 回退 |
|---|---|---|---|---|
| F1a 快照超期**且**周班停摆 | `generated_at`>8天 **且** `lastRunAt`>8天 | 先 read_transcript 查死因（悬挂/权限/零产物）；确诊后才修；修不了（平台层）→ 只报告 | 下次周窗（周日 20:00 PDT ±24h）内 lastRunAt 前进 + 快照刷新 **且 triggered_by=scheduled** | 无写动作，天然可退 |
| F1b 快照超期**但**周班在跑（班内落盘失效） | `generated_at`>8天 **且** `lastRunAt`≤8天 | 诊断写路径（脚本写失败/落错位/G-X118 同款）→ S3 自证步加装（若尚未装）+ 贴 Doctor 命令重跑快照恢复基线 | 下次周班跑后 generated_at 前进 且 triggered_by=scheduled | 无沙箱写动作 |
| F2 班消失 | 快照 diff 出现减号 | 🔴 **只报告，永不自动重建**（建班=权限扩张） | Doctor 裁定 | — |
| F3 description 漂移 | `list_scheduled_tasks` 的 description 与镜像 SKILL.md frontmatter description 比对不一致（diff 落诊断卡） | `update_scheduled_task` **仅传 description 参数**、taskId exact-pin；pre-image＝list 逐字返回入 audit | post-image＝再 list 逐字比对一致 | 再 update 回 pre-image 原值 |
| F3p prompt 本体改动（含 S3 步插入） | 方案批准/设计变更 | **一律 Doctor 终端**：取回 store SKILL.md 全文+SHA → 沙箱改 → 贴回或 Doctor 执行 → 再取回+SHA 复验（G-X162 判据④既定路径）。**沙箱禁传 prompt 参数**（读不到本体=盲写，G-X118+一字之差族合体） | 取回 SHA 与贴回内容逐字比对 | Doctor 侧持原文可回退 |
| F4 launchd 源↔装机不一致 | 快照 🔴 | 只报告+贴命令（沙箱碰不到装机位） | Doctor 执行 | — |
| F5 死树分叉 | 快照 🟡 | 不动（已知无害存量，08-02 已判） | 快照持续亮灯 | — |

### L3 · 验收（实施与验收分权）

- **修复完成 ≠ 修好**。验收只认机器证据，优先「下一次运行自证」谓词：`lastRunAt` 前进到预期窗口 / `generated_at` 前进 **且 triggered_by=scheduled**（手动跑假绿灯是 08-02 实测双向都犯过的病，验收尺子必须防）/ audit 行 schema 合规 / 回读比对逐字一致。
- F3/F3p 属中风险（动 live store 班）：由**未参与实施的 subagent** 独立复验（授权内可自主派）；复验报告仅作背书，不取得 ✓ 权。
- audit 行状态只允许 🔄/⚠️；✅ 只由 Doctor 或指定独立验收方落（G-X4）。**Doctor 本场授权「定时任务列入可代签代勾类别」指 TODO 销项，不覆盖 audit 行的 ✅ 落签**——防后续会话混读。

### 审计层（贯穿）

- `brain/permanent/_repair_audit.md`：append-only（**用 Edit 尾段追加，不用 Write 覆写**——G-X107）。
- 每行 schema（六元组）：`ts`(ISO) / `trigger`(硬证据) / `action`(动作+工具名+参数形状) / `rollback`(回退点) / `acceptance`(判据，必须含可跑命令或工具名) / `actor`(实施者) / `status`(🔄/⚠️/✅)。test_repair_loop.py 含 audit 行解析器，缺字段/空字段即报。
- audit 经 Doctor commit 后于 git diff 显形（G-X154：staged≠committed，**显形须等 commit，读侧以文件本体为准**）——修复器的行为是**另一个被巡检对象**，叉二由此闭环。

## 4 · 永不自动清单（负向边界）

1. 不新建/删除定时班（含 create/delete_scheduled_task）——建班=权限扩张；
2. 不改任何班的 cron 排期（排期变更=调度权扩张）；
3. 不 enable/disable 任何班（状态变更除外：Doctor 已裁定的具体暂停/恢复场景）；
4. 不动 launchd 装机位、不 commit/push（沙箱 git 禁令照旧）；
5. **沙箱不传 prompt 参数**（读不到 store 本体=盲写）——prompt 任何改动一律 Doctor 终端 SHA 往返；「字段级 diff」仅在参数级实现（只传 description，不传 prompt），prompt 没有字段内粒度；
6. 不用 glob/日期排序拾取治理资产（G-X162）；
7. 未确诊死因不动手（G-X141）；
8. 修复后不自签「已修好」（G-X4）；
9. 不改告警分级口径（G-X122）；
10. 修复循环自身不新增定时班（它的触发点是 /resume 与周班——用不定时的东西兜底，不许再造一个需要被巡检的新班）。

## 5 · 验证方案（负向注入 · G-X150 精神 · 持久化）

修复循环自己的 fail-fast 测试，落 `brain/.tools/test_repair_loop.py`，纳入复现：

1. **伪造快照超期**（注入旧 generated_at）→ F1 判定函数必须分臂：lastRunAt 也超期→F1a；lastRunAt 新鲜→F1b，且**不得**误报 F2；
2. **伪造「lastRunAt 新鲜+快照旧」**（今日 live 病例同构）→ 必须判 F1b「班内落盘失效」而非「周班停摆」；
3. **triggered_by 假绿灯回归**：triggered_by=manual 的快照不得被读成「周班在跑」，F1a/F1b 验收判据必须含 triggered_by=scheduled；
4. **F3 负向**：update 写错字段（错键/空串）→ 回读比对必须非零报错，audit 必须记录失败；
5. **越权负向（白名单外 fail-closed）**：诊断卡请求 F2/F4/排期变更/新建班 → 循环必须拒绝并回「只报告」；
6. **错靶负向**：F3 对**非周班 taskId** 发起 update → 必须拒绝；携带 prompt/cron/enabled/notifyOnCompletion 任一参数 → 必须拒绝（授权调用形态仅＝description 参数 + exact-pin taskId）；
7. **audit schema**：audit 行解析器对缺字段/空字段/非法状态词必须报错。

正常路径 exit 0 不证明 fail-fast——每条守卫配持久化负向用例（G-X150 判据原文）。
