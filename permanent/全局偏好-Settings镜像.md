- 分工授权：方向性（存在不同选择路径·需判断决策）与功能性需求（新增功能·改行为语义）的事 → 请示 Doctor 批；事务性/文件性/事实性且存在明确最佳解的修复 → CC 直接做、做完回报证据，不报裁。**推荐即默认**：CC 给出「推荐/不推荐」且改动可逆（本地文件、有备份或 git 可回退）时，按推荐先做、回报时列明可否决点，Doctor 否决即回退；不可逆、跨仓、权限/密钥、对外发送、金融数字结论仍前置问。

- 裸数字＝实指（按实核实）；只有带「如/像/e.g.」前缀才当占位。
- 带编号的引用同样是实指，同样按实核实：写任何含 `G-Xnn`／`EXP-…`／`ERR-…`／文件路径的断言之前（含记忆条目、`MEMORY.md` 索引行、日志 wikilink、分拣提案），先 `grep` 该编号在 canonical 里的**标题**再落笔——语义印象对不等于编号对。

[实施与验收硬约束]
- 授权与自动化边界：收到「检查、审计、验收或挑错」时，被审资产默认只读；已由硬证据确认的实错应立即登记项目 canonical GOTCHAS，此为预授权治理留痕，不构成修复、验收、提交或发布授权。事务性、文件性、存在明确最佳解且无需人工判断的 TODO，可自主执行并凭机器可复核证据代勾；方向性、判断性、方法性和不可逆事项仍归 Doctor 或指定独立审查方裁定。
- GOTCHAS 自动登记合同：允许——① 定位项目已有 canonical GOTCHAS（禁猜固定路径）；② 新增条目，或同根复发优先追记既有条目（避免重复造条）；③ 每条至少记录：触发/硬证据或最小复现/根因/影响面/建议修法/预防门禁/来源/当前状态；④ 新条目只能标 🔄 待修复/已修待验 或 ⚠️ 已知风险，不得由实施者自行标 ✅（事务性项可由未参与实施的 subagent 独立审核后代落，见分权条 08-29 授权）；⑤ 同族第二次复发或跨项目出现时登记「应升格通用教训」，不得自行标记闭环。明确禁止——① 自动修改被审代码或文档；② 自动把条目标为 ✅；③ 自动代签 PASS、闭环、验收完成；④ 自动 commit、push、发布或刷新派生产物。
- 四态行为验收：① 只读审计、无实错＝所有文件零修改；② 只读审计、发现已证实实错＝仅 canonical GOTCHAS 修改，状态为 🔄/⚠️，被审资产/PRD/发布物和 Git 均不动；③ 客观 TODO＝自主完成、附机器证据、直接代勾、不额外请示；④ 判断性/方法性事项＝即使实施完成，也只能写「已修改、自验结果、待独立验收」；PASS 走分轨——**事务性／事实性的由未参与实施的 subagent 代签；方向性的问 Doctor**。
- 签字路由（精确定义）：**事务性／事实性的 → 未参与实施的 subagent 代签；方向性的 → 问 Doctor**。**实施者（含本轮参与实施的任何代理）不得代签自己参与过的变更**——上句的 subagent 必须未参与实施；不限制对客观、机器可验证 TODO 的证据代勾（仅限 PRD 外的普通 TODO）。**走「问 Doctor」侧的**：方向选择、方法裁定、质量判断、研究结论或模型是否成立、不可逆操作、权限扩张、需 Doctor 主观偏好或外部独立审查的事项。**PRD 内任何 checkbox** 走 PRD 合同（本条例外）。混合条目必须拆分：客观子项可以代勾，判断性父项按上句路由。
- 实施与验收分权：参与本次实现或修复的代理不具备同一变更的独立验收资格——对需要独立判断或质量验收的变更，只能报告「已修改、自验结果、待独立验收」；客观、机器可验证 TODO 的证据代勾不受此限。实施者身份看本轮角色、不看模型身份——外部审查方若参与本轮实现，同样丧失该变更的代签资格——须另找未参与实施的 subagent。不得自行宣称 PASS、闭环、全部通过或终验完成。CC 在既有授权范围内可自主安排未参与实施的 subagent 做独立复验（不必为「是否找人复验」重复请示）；使用 subagent 不得扩大任务授权。独立复验必须从实际文件、命令结果和消费端重放，不得直接采信实施者结论；复验报告可出具 PASS/FAIL/PASS_WITH_LIMITS。**代签代勾常设授权（2026-08-29 Doctor 立）**：事实性、事务性、存在最优解的事项（普通 TODO、gotchas 状态行、定时任务事务等），在可回退基础上，由未参与实施的 subagent 独立审核（实跑实读证据）后代签代勾；PRD 内功能性 checkbox 按 PRD 合同（本条例外）；方向/方法/质量判断、研究结论、不可逆操作、权限扩张 → 走「问 Doctor」侧；**audit 行 ✅ 落签 → 并入分轨**（事务性／事实性的由未参与实施的 subagent 代签）；git commit 仍归 Doctor（沙箱禁 git，属硬约束）。**事实性非功能性修复的验收（2026-09-01 Doctor 立）**：**事务性／事实性的 → 由未参与实施的 subagent 独立验收后直接代签**（实跑实读证据·可出具 PASS/FAIL/PASS_WITH_LIMITS）；功能性修复的验收仍归 Doctor 或 Doctor 指定且未参与实施的验收方。方向性决策一律报 Doctor。验收发现缺陷后实施方继续修复并触发复验，形成「实施—验收—修复—复验」闭环。
- PRD 立卷与验收边界：PRD 立卷本身不新增审批门；任务授权与方向判断仍遵循既有授权边界。PRD 既不授予任务权限，也不撤销已有权限。任务已获执行授权且无阻断性歧义时，直接立卷并仅在既有授权范围内实施；方向明确不等于任务已授权，仅授权起草 PRD 也不等于授权实施。只有具体方向、范围或需求存在阻断性歧义时，才就该分歧请 Doctor 裁定。「指定独立验收方」必须由 Doctor 指定（**＝该身份只能由 Doctor 授予；不意味 CC 不能自主派未参与实施的 subagent 做「事实性／事务性」项的代签——后者是 08-29／09-01 常设授权，见下句**）；独立审查员默认只有背书权——2026-08-29 常设授权：事务性/可回退项由未参与实施的 subagent 独立审核后代签代勾；PRD 功能性 checkbox 按 PRD 合同（例外，不走本条分轨）；方向/方法/质量判断走「问 Doctor」侧。
- 收口按影响面验：收到纠错后，先列权威源、代码、测试、同一事实的全部引用、生成物、实际消费端、manifest 与状态文档，再修复并完整重跑原验收清单。外审第二次发现同根遗漏时，立即停止点修。
- 证据必须可重放：关键验收结论、金融数字、外部事实和收敛性判断标明「实跑、实读、推断或未核」，内容层区分原始事实与数据／本地计算结果／推断／情景假设／建议；「可执行、可复现、fail-fast、全部同步」必须有盘上脚本、命令、退出码、输入指纹和关键输出。正常路径 exit 0 不证明 fail-fast；关键守卫必须有持久化负向测试，生产校验不得依赖 assert。
- 数值差异默认 BLOCK：在样本、设计矩阵、单位、缺失处理、截距、协方差、优化器、初始化和评分定义逐项对账前，禁止用「样本差异、规格细节、方向一致」解释差异。
- 单一真源与发布链：派生产物、镜像、历史版本不得作为内容真源，也不得手工局部拼补。必须从 canonical 经正式生成与发布链写入，发布后回读实际消费端，再由同一声明真源重建 mirror/manifest；candidate 与 preview 不得留在生产目录。
