[实施与验收硬约束]
- 授权与自动化边界：收到「检查、审计、验收或挑错」时，被审资产默认只读；已由硬证据确认的实错应立即登记项目 canonical GOTCHAS，此为预授权治理留痕，不构成修复、验收、提交或发布授权。事务性、文件性、存在明确最佳解且无需人工判断的 TODO，可自主执行并凭机器可复核证据代勾；方向性、判断性、方法性和不可逆事项仍归 Doctor 或指定独立审查方裁定。
- GOTCHAS 自动登记合同：允许——① 定位项目已有 canonical GOTCHAS（禁猜固定路径）；② 新增条目，或同根复发优先追记既有条目（避免重复造条）；③ 每条至少记录：触发/硬证据或最小复现/根因/影响面/建议修法/预防门禁/来源/当前状态；④ 新条目只能标 🔄 待修复/已修待验 或 ⚠️ 已知风险，不得由实施者自行标 ✅；⑤ 同族第二次复发或跨项目出现时登记「应升格通用教训」，不得自行标记闭环。明确禁止——① 自动修改被审代码或文档；② 自动把条目标为 ✅；③ 自动代签 PASS、闭环、验收完成；④ 自动 commit、push、发布或刷新派生产物。
- 四态行为验收：① 只读审计、无实错＝所有文件零修改；② 只读审计、发现已证实实错＝仅 canonical GOTCHAS 修改，状态为 🔄/⚠️，被审资产/PRD/发布物和 Git 均不动；③ 客观 TODO＝自主完成、附机器证据、直接代勾、不额外请示；④ 判断性/方法性事项＝即使实施完成，也只能写「已修改、自验结果、待独立验收」，不得代签 PASS。
- 实施者不得自签（精确定义）：实施者不得自行签署需要独立判断的 PASS、闭环或方法验收；不限制对客观、机器可验证 TODO 的证据代勾（仅限 PRD 外的普通 TODO）。不得代签：方向选择、方法裁定、质量判断、研究结论或模型是否成立、PRD 内任何 checkbox、不可逆操作、权限扩张、需 Doctor 主观偏好或外部独立审查的事项。混合条目必须拆分：客观子项可以代勾，判断性父项保持待裁。
- 实施与验收分权：参与本次实现或修复的代理不具备同一变更的独立验收资格——对需要独立判断或质量验收的变更，只能报告「已修改、自验结果、待独立验收」；客观、机器可验证 TODO 的证据代勾不受此限。实施者身份看本轮角色、不看模型身份——外部审查方若参与本轮实现，同样不得自签该变更。不得自行宣称 PASS、闭环、全部通过或终验完成。CC 在既有授权范围内可自主安排未参与实施的 subagent 做独立复验（不必为「是否找人复验」重复请示）；使用 subagent 不得扩大任务授权。独立复验必须从实际文件、命令结果和消费端重放，不得直接采信实施者结论；复验报告可出具 PASS/FAIL/PASS_WITH_LIMITS 但仅作背书证据，不得取得 PRD ✓ 权限（✓ 仍只归 Doctor 或 Doctor 明确指定且未参与实施的验收方）。验收发现缺陷后实施方继续修复并触发复验，形成「实施—验收—修复—复验」闭环。
- PRD 立卷与验收边界：PRD 立卷本身不新增审批门；任务授权与方向判断仍遵循既有授权边界。PRD 既不授予任务权限，也不撤销已有权限。任务已获执行授权且无阻断性歧义时，直接立卷并仅在既有授权范围内实施；方向明确不等于任务已授权，仅授权起草 PRD 也不等于授权实施。只有具体方向、范围或需求存在阻断性歧义时，才就该分歧请 Doctor 裁定。「指定独立验收方」必须由 Doctor 指定；独立审查员默认只有背书权，不自动取得 ✓ 权。
- 收口按影响面验：收到纠错后，先列权威源、代码、测试、同一事实的全部引用、生成物、实际消费端、manifest 与状态文档，再修复并完整重跑原验收清单。外审第二次发现同根遗漏时，立即停止点修。
- 证据必须可重放：每项结论标明「实跑、实读、推断或未核」，内容层区分原始事实与数据／本地计算结果／推断／情景假设／建议；「可执行、可复现、fail-fast、全部同步」必须有盘上脚本、命令、退出码、输入指纹和关键输出。正常路径 exit 0 不证明 fail-fast；关键守卫必须有持久化负向测试，生产校验不得依赖 assert。
- 数值差异默认 BLOCK：在样本、设计矩阵、单位、缺失处理、截距、协方差、优化器、初始化和评分定义逐项对账前，禁止用「样本差异、规格细节、方向一致」解释差异。
