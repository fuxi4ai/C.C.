## G2 · 事件时钟（events 表 schema 变更）

### 现状 gap（attribution.db 实读）

events 表列：`event_date`（自然日）/`type`/`title`/`detail`/`source`/`created_at`/`trade_date`（人手映射交易日）。**无公开时刻戳**，盘后事件与盘中事件同记当日：

- 07-29 CENTCOM 打击 IRGC（20:00-22:00 ET·盘后）trade_date=07-29——市场反应实际在 07-30（台账已另注「盘后」字样，但取窗按 07-29 走）
- 08-02 周日事件（Trump 取消袭伊 / OPEC+）trade_date=08-03 ✓ 映射正确
- 其余 24 行盘中/会期事件映射无误

### 方案（推荐案）

1. **加列不动存量**：`ALTER TABLE events ADD COLUMN first_public_ts TEXT`（ISO8601 UTC·精确分钟）+ `ADD COLUMN effective_trade_date TEXT`。**trade_date 存量值不动**（A 阶段九轮验收的数字全部锚在它上面）。
2. **close-cutoff 规则**：16:00 ET 收盘后公开 → effective_trade_date = 下一交易日；盘中公开 → = 当日；周末/假日 → 下一交易日。规则写入台账事件时钟节（预注册）。
3. **回填 27 行**：逐条补 first_public_ts（信源：台账 detail 已有时刻 + VV 回执 + WebSearch 补缺）+ effective_trade_date（按 cutoff 规则机算）。预期唯一修正行 = 07-29 CENTCOM（effective→07-30）。
4. **消费端切换**：update_attribution_db.py / export_mech_data.py / 值守班取窗逻辑改读 effective_trade_date（缺则 fallback trade_date）。
5. **冲击检查（关键）**：07-29 effective 平移一日后，重算 2-P 该事件 CAR——**已交 VV 验收的 A 阶段数值若变动，须出差异对照表呈 Doctor + 知会 VV**，不静默改账。

### 迁移方式

写库走 Mac 原生侧（SQLite 挂载写库裁定）：备份 attribution.db → Doctor 终端跑迁移+回填 SQL → CC 沙箱只读验证（27 行核对+07-29 修正+窗口重算对照）。
