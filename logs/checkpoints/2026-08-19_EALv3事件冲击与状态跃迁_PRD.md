> **文档身份与真源声明**：本文件于 2026-08-19 由 CC 经 Doctor 批准（方向批 + 逐文件映射清单确认）从 Codex staging 单向迁移入 Brain canonical（`logs/checkpoints/`），自此为 EAL v3 功能/需求验收基线真源；Codex staging 副本不再维护。吸收侧适配 divergence 见 `backtest/eal_v3/ABSORPTION_ADAPTATION.md`。不得把 staging 与 Brain 维护成两套并行真相。

## 0. 产品结论

EAL v3 不再把“每天都解释出一组权重”作为主产品。主产品改为：

1. 当前 staging 阶段先对事件/状态跃迁输出无控制的 **daily shadow compound gap**，回答观察行情相对同长度日基线偏离多少；正式 CAR 与 local projection 保留为后续独立估计量；
2. 分别刻画冲击后的最大不利变动、持续时间、恢复速度、最大反弹与进入/退出状态的不对称性；
3. 在无事件日保留日频测量、描述性 baseline reference、状态监控和漏标事件诊断，但不强迫输出虚假的逐日归因份额；
4. 对重叠事件先合并为 cluster，无法分离时明确标记“簇内不可归因”，不把同一段价格变化重复分给多个事件；
5. “权重”仅作为有条件的二级展示。主结果是百分点、基点、标准化冲击和置信区间，不强制加总为 100%。

## §一 · 任务目标与范围

### 1.1 用户要回答的问题

- 宏观、货币政策、地缘政治、公司事件，或它们形成的混合簇，在首次公开后给目标资产带来了多大的边际冲击？
- 冲击的“杀伤烈度”有多强：初始偏离、各 horizon 的复利 shadow gap、最大不利变动、到达谷值所需时间分别是多少？
- 紧张状态缓和或退出后，反弹力度、恢复时长和进入/退出不对称性如何？
- 结论是高频可识别、日频准实验、描述性关联，还是当前不可识别？
- 哪些日子没有可识别事件，因而只能报告基线偏离而不能报告事件权重？

### 1.2 成功定义

用户查看任一已关闭事件簇时，应能看到：事件事实、首次公开时钟、分类版本、`state_type`、状态进入/退出标签、episode/独立组、最大报告 horizon、窗口定义、daily shadow compound gap、烈度/反弹指标、不确定性、样本门、识别等级、排除原因和可追溯证据。系统不得用当日价格结果反过来定义事件类别或强弱；当前 shadow 控制集必须为空，不能把任何控制项静默带入。

### 1.3 范围与边界

#### 1.3.1 纳入范围

- 事件事实、事件时钟、price-blind 分类、状态与状态跃迁、重叠簇、市场观测、描述性 baseline reference、估计结果、审计结果的结构化 schema；
- 当前 daily shadow 的报告 horizon `h∈{0,1,3,5}` 与可用时的高频扩展合同；所有重叠识别统一使用最大报告 horizon；
- 宏观、货币政策、地缘政治、公司/财报及 `other` 原子事件族；
- “进入状态”“退出状态”“状态内升级/缓和”等 transition；
- 个体事件/簇的机械描述与同类事件的池化估计；
- v2.3 共变模型和机械回测的兼容、影子运行、退役与回滚策略；
- 面向研究与决策的可审计输出及用户界面。

#### 1.3.2 不纳入范围

- 对每个交易日强制生成加总为 100% 的因果解释；
- 用同日 VIX、油价、利率、信用利差、行业 ETF 或目标资产价格变化定义事件方向、严重度或类型；
- 在重叠窗口内无识别依据地拆分单个事件贡献；
- 把解释性同日共变模型宣传为预测模型或因果模型；
- 用文件存在、grep 清零、hash 一致代替功能验收；
- 本 staging 文件直接覆盖 Brain 真源、数据库、Gateway 或正式 artifact。

#### 1.3.3 关键术语

- **event**：具有外部事实来源和首次公开时点的原子事件。
- **state**：跨期持续的背景状态，只调制冲击传导，不天然决定每日方向。
- **transition**：状态进入、退出或等级跃迁，可作为离散冲击处理。
- **cluster**：估计窗口重叠而无法独立观察的事件连通分量。
- **episode**：同一底层冲击或持续事态的一组相关事件；同一 episode 即使形成多个 cluster，也不能重复抬高样本量。
- **independence group**：预注册的独立计数单位 `independence_group_id`；默认等于 `episode_id`，也可把已知相依的多个 episode 合并为一组。
- **price-blind**：分类时不得读取事件后的市场价格、波动率或由其构造的标签。
- **总效应**：事件经所有自然传导渠道作用后的整体边际影响。
- **直接条件关联**：控制中介变量后剩余的同日关系；不得冒充总效应。
- **daily shadow compound gap**：从最早成员前一交易日收盘到最后成员加 horizon 的观察复利收益，减去同长度日基线复利收益；它是描述性 shadow 指标，不是原先逐日异常收益求和的 CAR。
- **eligible independent group**：对应窗口已完整结束、数据与规则通过、且按 episode/预注册相依关系去重后的独立样本单位。

## §二 · 交付标准（Acceptance Criteria · 验收主体＝功能/需求）

下列 checkbox 是**功能验收状态**。起草态一律为 `[ ]`。验收证据可以是测试、样本、日志、截图或人工复核记录，但证据本身不等于需求已经被独立验收。

### A. 功能需求

- [ ] **R1 · 输入合同可执行**：系统能按 `METHOD_CONTRACT.md` 接收并校验事件事实、分类、时钟、状态、市场观测和配置；`eal-event-registry-v3.2` frozen registry 的 `state_type` 必填，事件/结果 `identity_sha256` 唯一。分发的 Draft 2020-12 JSON Schema 是可携 shape 合同；当前 stdlib runtime 不伪装通用 JSON Schema 引擎，而是以持久 parity test 锁定 schema 的 `required/properties`、版本化 fact allowlist 与 parser 字段集，再由 `parse_event` 对每行执行 exact-shape、类型/枚举和完整跨字段、时间、身份、状态、来源 semantic 门。schema parity 与 semantic/runtime 门须联合通过，任一不能替代另一层。缺失主键、重复身份、非法枚举、时区不明、窗口越界、引用不存在或可报告性矛盾时 fail-closed。
  - 用户可感知结果：错误数据不会静默进入估计或 artifact。
  - 验收方法：以一组合法 fixture 和每类非法 fixture 运行入口；合法输入完成，非法输入分别非零退出并输出稳定错误族与精确行键。
  - 可重放证据：待实施者填写。

- [ ] **R2 · 事件时钟唯一且可审计**：每个进入 `eal-event-registry-v3.2` 估计的事件都记录 `source_published_at_raw`、IANA `source_timezone`、`first_public_ts_utc`、`first_public_lower_utc/upper_utc`、`timestamp_precision`、`clock_quality`、权威来源和派生 `effective_trade_date`。当前 frozen runtime 只接受 `minute/hour`，分别要求 `reported_minute/reported_hour`、`first_public_ts_utc=lower` 及 1 分钟/1 小时半开 bounds；仅日期或未解时钟留在 intake/排除态。原文时区/offset 解析与 UTC lower 不一致、本地时间落 DST gap/fold、bounds/quality 不匹配、事件早于冻结日历首日、或无法在日历覆盖内求得下一交易日时 fail-closed；盘前、盘中、盘后、周末/休市和修订发布按确定性规则处理。配置的 `market_data_as_of_utc=market_data_snapshot.observed_at_utc` 且不得晚于系统 UTC；每个 frozen event 的 `first_public_ts_utc/first_public_lower_utc/first_public_upper_utc/classified_at_utc/state_known_at_utc/expectation_known_at_utc`（后者可空）均不得晚于 as-of。违反者分别稳定报 `EAL_FUTURE_ATTESTATION` 或 `EAL_EVENT_METADATA_AFTER_AS_OF`，正式 CLI 不接受 caller 覆盖系统时钟。
  - 用户可感知结果：同一事件不会因人工日期写法不同落到不同窗口。
  - 验收方法：固定时钟矩阵覆盖至少纽约盘前、盘中、盘后、周末、DST 两侧、低精度时间与修订事件；逐项比对期望交易日和排除码。另将 config as-of/snapshot observed-at 置于系统 UTC 之后，并逐一将 6 个 event metadata 时间置于 as-of 之后，核对稳定错误族。
  - 可重放证据：待实施者填写。

- [ ] **R3 · 分类严格 price-blind**：事件族、方向、严重度和 transition 标签只能读取版本化 structural-fact allowlist（事件事实、权威文本、预先存在状态、事件前可得预期及事实尺度）；改变事件后所有市场价格而保持 allowlisted 输入不变，分类结果逐字段不变。Macro `eal-facts-macro-v2` 的 exact payload 只含 `release_code/actual_value/consensus_value/measurement_unit`，`release_code` 只允许合同内 9 个宏观发布代码；earnings `eal-facts-earnings-v2` 的 exact payload 只含 `issuer_code/release_code/actual_value/consensus_value/measurement_unit`，`issuer_code` 当前只允许 `^CIK-[0-9]{10}$`。`SPY/SP500` 等市场代码不能冒充 release/issuer identity。`price_blind_attestation=true` 只是可追责声明，不是技术证明；还必须同时通过物理/逻辑数据视图隔离、字段 denylist、输入 lineage/hash 和价格置换测试。
  - 用户可感知结果：不会出现“因为跌了所以判为利空，再证明利空导致下跌”的循环解释。
  - 验收方法：metamorphic test 随机置换或极端改写事件后价格列，比较分类输出 hash；另对禁止字段注入读取哨兵，并对 macro 未登记 release code、earnings 非 CIK issuer、额外 payload key 及 `SPY/SP500` 假代码做负测。
  - 可重放证据：待实施者填写。

- [ ] **R4 · 重叠事件形成确定性 cluster**：强制 `overlap_horizon=max(reporting_horizons)` 构造重叠连通分量；cluster 从最早成员开始，输出窗口的右端以 `last_member_anchor` 为锚并覆盖至 `last_member_anchor+h`；`cluster_id` 是对 exact `cluster_identity_material={cluster_rule_version,window_spec_id,maximum_horizon,boundary_rule,member_identity_sha256(sorted)}` 计算所得完整 64 位 SHA-256 digest（允许固定 namespace 前缀但不得截断 digest），且对输入顺序不敏感。每个 cluster 及每条结果必须输出并互相核对 `cluster_id/cluster_identity_sha256/cluster_identity_material`，禁止只留显示成员名而丢失身份材料；跨事件族簇派生为 `mixed`，但原子事件族不被覆盖；多成员簇未实现分离时用 `not_separable`，单成员用 `not_applicable`。
  - 用户可感知结果：同一段行情不会被多个重叠事件重复认领。
  - 验收方法：覆盖链式重叠、边界相接、完全嵌套、不同输入顺序、无重叠和开放簇 fixture；验证 ID、成员、状态和不可分离标志。
  - 可重放证据：待实施者填写。

- [ ] **R5 · 状态与 transition 语义分离**：系统把持续状态记录为条件变量，把进入/退出/升级/缓和记录为冲击事件；frozen event 均有非空 `state_type`（不适用时用 canonical sentinel）。无跃迁 event 的 runtime registry/result JSON 字段固定为 `transition=none`，SQL event/result row 固定映射为 `transition_type=none`，adapter 只改字段名、不改值；成员 transition 不一致时 cluster 可派生 `mixed`，而 `state_transitions` 实体表只存真实 `entry/escalation/easing/exit`，不为 `none/mixed` 制造伪跃迁行。聚合只能发生在相同 `state_type + state_rule_version` 内；规则版本或状态尺度不兼容时禁止合池，须有显式映射/版本迁移。当前实现只承诺预注册 SPY `higher_is_favorable` orientation 下的 adverse/rebound/recovery 派生，不承诺中性 `entry_exit_gap_difference/entry_exit_gap_ratio`；后两者是未来独立估计项。相同规则可重放生成一致 transition；进入与退出分别计算，不预设对称。
  - 用户可感知结果：能分别回答“进入紧张状态杀伤多大”和“退出紧张状态反弹多强”。
  - 验收方法：用合成状态序列验证进入、维持、升级、缓和、退出和缺口行为；核对事件表与状态表无角色混淆。
  - 可重放证据：待实施者填写。

- [ ] **R6 · Current daily shadow 口径唯一且无控制**：从最早成员前一交易日收盘到 `last_member+h` 计算 observed compound return，再减去同长度 compound daily baseline；该 trailing-mean baseline 是透明 reference path，**不是已识别的无事件反事实**。baseline 构造只排除运行截止前已登记且已冻结的事件窗口，不能事后侦测并排除未知事件；当前 `control_set` 必须为空。市场面板必须绑定 exact `market_data_snapshot(snapshot_id,database_sha256,source_version,quality_status,observed_at_utc)`，其中 `quality_status=sealed_final`、`observed_at_utc=market_data_as_of_utc`、DB SHA 与实际输入逐位一致。每个 target/每个 horizon 分别验证全部所需 session 的 snapshot availability 且 `session_close_utc + data_finality_lag ≤ as_of_utc`。finality cutoff 前无论该日价格行是否已到，都只进入相应 `*_unfinalized_dates`，不得提前记作 missing。事件窗口仍开放时返回 `status=open/reason_code=EAL_EVENT_WINDOW_NOT_FINAL` 并保留已经 final 的前缀 `horizons`；每个前缀行携 `data_final_at_utc/data_finality_status=final`，但落库只能标 `descriptive_only`，所属 cluster 的 `n_closed_clean=0` 且不得进入 pool。baseline 尚未 final 时返回 `status=open/reason_code=EAL_BASELINE_NOT_FINAL`、列出 `baseline_unfinalized_dates` 且不输出 horizon。只有 cutoff 已到而应有行仍不存在，才分别记入 `window_missing_dates` 或 `baseline_missing_dates`：事件窗缺行返回 `status=not_estimable/reason_code=EAL_EVENT_WINDOW_PRICE_MISSING/horizons=[]`，baseline 缺行返回 `EAL_BASELINE_PRICE_MISSING`；冻结 calendar 不覆盖窗口报 `EAL_EVENT_WINDOW_CALENDAR_INCOMPLETE`，baseline 观测不足报 `EAL_BASELINE_INSUFFICIENT_OBSERVATIONS`。任一缺失或未 final 都以 target、horizon、日期清单、阶段和稳定 exclusion code 显式输出，不得补 0、删日或缩窗。该字段命名为 shadow gap，不得复用 CAR/CAAR 名称；正式 CAR/local projection 留待后续估计器。
  - 多成员 H0 前 canonical 边界：若运行时点早于最后成员 H0 finality，即使更早成员对应的负 `tau` 数据已经 final，也不存在可发布的非负 horizon。target 必须为 `status=open/reason=data_finality_lag_not_elapsed/reason_code=EAL_EVENT_WINDOW_NOT_FINAL`、`horizons=[]`、`window_missing_dates=[]`，并把最后成员 H0 交易日列入 `window_unfinalized_dates`；除此只保留登记的 empty-horizon 最小审计字段，不得生成 estimate、baseline path、min/max 或 recovery。adapter 只记录每 target 1 条 exclusion，不制造 impact row。
  - 用户可感知结果：同一 cluster 的观察窗完整覆盖所有成员，且不会把描述性 shadow 数字误读成原先 `ΣAR` CAR 或受控因果效应。
