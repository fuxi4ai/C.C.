# PRD · EAL目录与文件格式标准

## §一 · 任务目标

**动机**：EAL 自 2026-07-28 起走过七段（归因台账 → v3 影子 → 宏观事件回测 → 估值预期台 → 星空前端 → 日内行情线 → 量化案例范式），实为三条线叠在一个目录：A 归因研究（现行主线，Doctor 10-17、10-30 两次裁定）、B 预期发现（09-07 订正为 A 的输入层）、C 消费前端。总入口 README 与 PRODUCT 停在 09-08 只写 B 线；frameworks/ 六件中四件不是现行框架；根目录十个散件无索引；「事件/锚/台账/框架」四词同名异义。接手者按 README「先读 README 与迭代记录」会得到错的主线。

**范围**：三批。批一＝README「当前目标」重写为归因研究三层 + 各目录入口导航、新增 `frameworks/INDEX.md`、新增 `records/` 收根目录五件散件。批二＝frameworks/ 四件非现行件与两件研究材料工作记录归档或迁移、原位留指路、现行引用改指。批三＝带日期文件名统一 `YYYY-MM-DD-主题`、各类文档 frontmatter 契约落实并加机器校验。

**主目标表述（Doctor 2026-11-05 采纳）**：EAL 是事件与行情归因研究实验室。以 SOX 为主对象，回答「某事件或行情形态，在什么状态下，经哪些渠道，转化为怎样的价格实现」。产出三层按样本量与机械化程度晋升：① 定量事件库（n≥30，attribution.db）② 案例（cases/ 事件冲击个案、case-studies/ 行情案例）③ 框架（从案例或定量库晋升的分析框架与相关性结论，带证据等级与来源案例）。机构预期是 ①② 的输入参照；前端是消费层。

**Doctor 原始指令**（逐字引用）：
> "分析整个EAL（因为这是个多阶段融合项目，最早是分析美股行情归因的，又连续变为事后事件解释力、预期发现等，最近又加上了日内行情分析和机构观点汇总，有些混乱），厘清现在的项目主要目标和发展方向，建立清晰的文件格式标准，可以有casestudy（案例分析文档）、framework（从案例分析中晋升的分析框架和相关性结论）等必要文件夹和相应的索引、迭代记录等。"
