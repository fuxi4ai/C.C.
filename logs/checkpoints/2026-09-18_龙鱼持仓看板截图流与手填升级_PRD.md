# PRD · 龙鱼持仓看板截图流与手填升级

## §一 · 任务目标

**动机**：Doctor 的持仓分布于三个券商账户（太平洋证券、招商证券普通、招商证券信用），此前 holdings.json 靠零星手工录入（有「待录入股数成本」占位残留），维护断点且无清仓留痕。本任务把「每轮三张券商截图」固化为持仓真源的唯一更新流，并在二级详情页补上持仓纪律两栏（建仓理由、预期价格），让买卖决策有据可循、可复盘。

**范围**：① 截图提取流（CC 目视提取 → 对账 → 备份 → 落库 holdings.json → 重建看板 → 重推 artifact → 回报对账表）；② holdings.json 扩展（account/reason/target_price/liability/closed）；③ 持仓看板详情面板与编辑器加两栏（最小改动，不重新设计 UI）；④ 三账户统合展示维持现状（Doctor 中途纠正：无需分组）。

**Doctor 原始指令**(逐字引用):
> "Artifact "longyu Stock library"中的"持仓看板"进行以下升级：1、我之后会以"太平洋证券"、"招商证券普通账户"、"招商证券信用账户"的顺序，每次传3张截图，截图中即为我所有的持仓信息。CC你从截图中提取标的、股数、成本、市值，现金余额等信息。价格从数据库拿，港股等数据库没有价格的，从截图拿价格；截图中没有的标的，说明卖掉了，从持仓中清除。2、在标的二级详情页，增加可以手填的"建仓理由"和"预期价格"栏目，帮助持仓纪律的执行。"

**中途修正**(逐字引用):
> "错了，三账户统合展示，无需分组。"
> "在目前界面的基础上最小改动即可，无需重新设计。"

**方向裁定**（AskUserQuestion · 2026-09-18 四项全按推荐）：
1. 手填持久化=MCP桥直写+会话兜底（MCP 桥不可用自动退复制-贴回）；2. 数据层加 account 字段（当时推荐分组展示，已被中途修正推翻——展示统合，字段保留仅作来源追溯）；3. 提取落库=对账+直接落库（备份可回滚）；4. 信用账户=余额+负债双记。

**任务规模估算**:
- 预计涉及文件数: 5 个改（holdings.json / board_data.py / build_holdings_board.py / SCHEMA.md / build_dark_board.py 重跑即带出）+ 1 个新（update_holdings_from_screenshots.py）
- 预计耗时: 2-3 小时
- 涉及项目: 龙鱼五力（Database/龙鱼-标的分析库 · 独立 git 仓）
