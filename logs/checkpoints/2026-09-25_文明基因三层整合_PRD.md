# PRD · 文明基因三层整合

## §一 · 任务目标

**动机**：PEC 的「文明基因」目前有 **14 套并行清单**（盘点见 `raw/2026-09-25_analysis_文明基因并行清单盘点与整合方案.md`），且存在五个可核的结构性问题：无跨套映射表 · `G-NN` 三重命名空间冲突 · 星空 25 颗的 `provenance` 指向不存在的文件（9/25 个名字在 `case-studies/` 里零出现）· 两套汇总（星空 25 / 星云 88）各自策展且彼此几乎不相交 · 最厚的案级清单（CS-10 有 36 条）被两套汇总双双忽略。根因是**「汇总层各自策展」**。

**要做什么**：按 Doctor 裁定的**三层设计**把这些清单收敛到单一真源——每文明一份 `文明基因清单.md`（L1）→ 机械汇总成总表（L2，含跨套映射）→ 星空/星云/A2 只渲染（L3）。**口径按「中」统一**：文明的**层级持续属性**（含地理/资源/制度要件），**排除分析者的结论**。

**⚠ 范围扩充（2026-09-25 20:40 Doctor 追加裁定）**：整合**不仅要收敛真源，还要把被压平的内容层级显式化**。新增的机器证据——D 套 88 条的 `category` 字段有 63 个值，而归类后它**同时在标三个正交集**：**轴 A·抽象层级** 53 条（`L1` / `L1.补充` / `a.N` / 案例具体层 / 复合层）· **轴 B·其他框架归属** 30 条（`F-04` / `H-08` / `H-09` / `F-08`）· **轴 C·来源类型** 5 条（学者命题 / 实证事件）。⇒ D 套不是"层级乱"，是**层级被压平**。**若 L2 只做 id 映射，会把这三轴继续压平、等于把 D 套的错误重做一遍。**

**⇒ L2 每条须带四轴**：`level`（元层 / 文明层 / 子主体层 / 条目层 / **复合层**）· `object_type`（基因 / 命题 / 事件 / 框架应用）· `civilization` · `sub_entity`；**L1 清单按 `level` 分节**（CS-09/CS-10 现有格式即正确样板）。

> **两条必须同时遵守的约束（本场实读所得）**：① **复合层是横切的、不是第 5 层**——耶路撒冷复合跨 CS-01＋CS-09＋CS-02/03；纯树形设计会漏掉它 ⇒ `level` 取值含「复合层」，但它与 `civilization` 是**多对多**，L2 不得把它折进单一文明。② **「层」字在 PEC 已被占用两次且不是同一把尺**——F-07 的 `L1 / L1.补充 / L3`（命题抽象度）与 CS-05 的 `底层 / 中层 / 表层`（文明内部结构），再叠本方案的治理三层（真源 / 汇总 / 展示）＝三把尺 ⇒ **三把必须分别命名，不得共用一个「L1」**（见 N4）。
