## 一、治理与验收：从「打勾权 Doctor 独占」到「签字分轨」

**v2.0 基线**：propose-then-confirm · 打勾权 Doctor 独占、起草权可下放 · 独立审查者范式 · 双重门控。
**v3.0 增量**（本主题是这批演进最大的一处）：

1. **签字分轨（判据＝判事实 / 判选择 · 2026-09-19 立 · 显式取代「打勾权 Doctor 独占」表述）**——判事实（事实性的核查/批复/签字/验收）→ 未参与实施的 subagent 审核者独立核验后**自主**落签，不攒批问 Doctor；判选择（方向性决断 save/选型/裁定）→ **直接**开问题问 Doctor（AskUserQuestion＋推荐/不推荐＋理由）。例外：PRD 内 checkbox 走 PRD 合同。出处：Settings 块一签字分轨条 · G-X136（打勾权分轨·客观证据代勾常驻授权，演进路径落地）· G-X200（禁止类规则必须同条给「默认动作」——「落签路由」句即其正面应用，否则执行者把禁止读成「上交」）。
2. **常设代签授权与复验闭环（2026-08-29 / 09-01 立）**——事实性/事务性/存在最优解的事项（普通 TODO、gotchas 状态行、定时任务事务等），在可回退基础上由未参与实施的 subagent 独立审核（实跑实读证据）后代签代勾；事实性非功能性修复的验收同路由，可出具 PASS/FAIL/PASS_WITH_LIMITS；验收发现缺陷 → 实施方修复 → 触发复验，形成「实施—验收—修复—复验」闭环。**为什么复验者必须未参与实施**：G-X202——实施者自行修补会反复引入新错，三轮复验的机器证据显示新错出在「修」这个动作里。
3. **报裁边界两限（2026-09-01 修订）**——请示只留两类：方向性（存在不同选择路径/需判断决策）与功能性需求（新增功能/改行为语义）；事务性/文件性/事实性且存在明确最佳解的修复直接做、做完回报证据，不报裁。
4. **PRD 立卷边界**——PRD 是功能/需求的验收基线，不是审批单：立卷不新增审批门、不授任务权限；方向明确≠任务已授权，仅授权起草 PRD ≠ 授权实施；只有阻断性歧义才请 Doctor 裁。
5. **治理服务于任务完成（G-X166）**——风险分级按影响面配验证强度（低风险＝最小充分验证，不机械加 PRD/独立验收/治理文件）；警告默认不阻断；新规则须说明防什么＋何时退役。
6. **规则修订必须替换上游旧文（G-X151）**——禁文末追记并存双轨（同根四次复发实证：RISK-002 第三次升格 · PEC CS-10 第四次 · 见 G-X151 追记）；传播按「改动处 × 引用处」影响面矩阵执行；条目升格进全局层过四条判据（跨项目＋每轮可能踩＋≥2 次同根复发＋能写成一句机械命令 · 2026-09-26 立）。
7. **改写与审计的自身防护**——大面积改写既有文档前必须先出 diff、先留副本（G-X196）；审计台账别内嵌被审文档——它会自我过期，并把复验变成无界循环（G-X195）；「不落盘」指令下的独立复验证据必须回填进被复核件、或由下一轮复核者书面转述销账，否则证据链断裂（G-X222）。
8. **判据自身也要被核**——我给出的验收判据本身也要核，判据错比结论错更坏（G-X120）；判据三重失效＝没被执行/无分辨力/空跑也绿（G-X218）；「容易核的代理指标」冒充判据——核之前先写下「我要判的是哪一句事实」（G-X211）；凡设排除必须声明规则＋报出被排除的量（G-X213）；判据里的 needle in haystack 必须防空串（G-X203）；收敛结论前先过「判别力」门——假设相反时该观测面若不变，它就不是证据（G-X190）。
9. **编号引用也是实指（2026-09-26e 立）**——写任何含 G-X/EXP/ERR/文件路径的断言之前，先 grep 该编号在 canonical 里的标题再落笔；语义印象对不等于编号对。

## 二、数据真实性：从「不造假」到「不自欺」

**v2.0 基线**：宁可缺数不可假数 · source+asof+credibility · 先核实再 promote · 按时效分库 · 口径冲突先比时效粒度。
**v3.0 增量**：

1. **叙事载荷词防污染（G-X228 · 2026-10-12 立）**——涉争议话题：行为事实照用，叙事定性双口径并列（一方口径≠基线）。
2. **数字必须实读，不许凭叙事配数**——事件研究数值必须 db/磁带实读，禁凭叙事方向配数（G-X148）；研究稿/札记里的估值数字是时点快照，引用前必须实拉当日值（G-X140）。
3. **报缺陷前先排自查**——「我读不到」≠「源头没有」，报缺陷前先把检索面写进结论句（G-X216）；工具/环境自身的假象会被读成被检对象的缺陷——先自问「这会不会是我的探针错了」（G-X214）；统计/判据要用的函数必须用真身，复刻一份近似件量到的是你自己写的那个近似（G-X215）。
4. **时间纪律族**——跨源日期/时间比较先归一（格式与时区），一夜两次假结论实录（G-X144 / G-X181）；age/时间戳字段先问「距什么」再判超界——观测期/发布日/采集日三轴不可混（G-X171）；跨日会话先对表，时间敏感判断前必重跑 date（G-X100）；沙箱 VM 时钟初始不可信——新鲜度判断用 env 日期＋宿主文件 mtime＋date 三重对表（G-X168）。
5. **数字的边界声明**——数值列不得落定性文本与分项口径（G-X152）；份额/市占率必带分母池（G-X159）；报计数之前先写清「按什么计」——两种口径的数不可比、不可相减（G-X209）。
6. **材料判据三违例（G-X156）**——表态不入判据·行为胜宣称·拐点不推终局；把自己的判断写成「证据显示」是层级错，引文核对抓不到（G-X194）；态度/意图判断必须双信道——「做了什么」推不出「说过什么」（G-X126）。
7. **引录与改写防护**——「引了」≠「读了」，引用保真抵挡不住漏读同文件的相反处（G-X199）；照抄体例＝一次未经核验的断言搬运——体例可抄、体例句里的事实不可抄（G-X217）；改写既有文档时顺手写下的新定量断言必须回代验算（G-X189）。
8. **实体与权威的判据族**——实体错配族统一判据：别名须与节点同指，「同名」是待判命题不是结论（G-X161 / G-X198）；图谱旧叙事锚不标时效/未退役会被下游判「编造」（G-X163）；在 canonical ≠ 是权威——自撰理由迁入未带来源标记会被下游当成系统原有（G-X207）；grep 命中关键串 ≠ 现行在场——留痕/引文/围栏会保留关键串（G-X208）。

## 三、写入安全与守恒：从「防写坏」到「防并发与漂移」

**v2.0 基线**：safe-wrapper · 守恒断言 · 快照基线 · 深合并防薄冲富 · 改动前两向检查。
**v3.0 增量**：

1. **重生成与批改的守恒**——整文件重生成必附「下架清单」，wholesale 重写会静默夹带未批准的删除（G-X130）；批量改造脚本「断言失败＝整批未落盘」——exit 1 之后别默认改过的都写了（G-X225，G-X8「已落盘假象」的脚本版）。
2. **挂载盘 SQLite 写库协议（G-X131）**——/tmp+cat 仅应急；常规＝停写窗口＋backup API＋原子替换＋查并发。
3. **共享与并发**——共享库整库快照放回会覆盖他人写入，integrity ok 证明不了不丢数据（G-X174）；并发接力下的资产版本重探——引用自己早前落盘的东西前先重探它现在的版本（G-X117）；双场并行竞写：认场→合流→不静默覆写→报告收口（G-X143 / G-X179）。
4. **资产的持久与实证**——跨会话执行资产必须落持久位置，沙箱 outputs 随会话蒸发，「统计还在」≠「明细可恢复」（G-X176）；会话 transcript 是资产——判「遗失」前先实挖，挖不到走等价路径（G-X177）；档案声称「文件已落盘」≠文件存在，引用前必 test -f / 哈希实查（G-X164）。
5. **坐标与编辑的脆性**——Edit 精确替换同族三事故：空串切片破坏文件头/前置破坏/同型代码块 old_string 误落位置（G-X158）；跨文件坐标是易腐品——引用外部件的行号必须在改完之后重取一次（G-X206）；对并行维护的共享文件引「行号」＝引用脆性——坐标被别场插入挤走、消费端全部失位、闸器假红（G-X221）。
6. **发布链洞族**——源↔装机分离＝发布链洞族，改装机位必回写源并双端对拍（G-X231）；异地部署点补丁必须回流源仓、发布链换入后加哨兵（G-X169）；部署即归档——部署命令必须自带清理段，无主残留三次复发（G-X180）。
7. **备份与归位流程**——备份归位两抽屉：archived/ 收退役真件、_bak/ 收改前快照，别混（EXP-20260928-001-S）；改挂载文件的归位流程：cp 到临文件→改→核写前 SHA→mv -f，脚本失败即中止、不得继续归位（EXP-20260926-007-T）。

## 四、沙箱/环境边界：从「FUSE 家族」到「身份与通道纪律」

**v2.0 基线**：FUSE 写限制 /tmp 中转 · 平铺挂载路径纪律 · 断言环境事实前先实测。
**v3.0 增量**：

1. **终端命令通道纪律**——沙箱 git 禁令边界＝「一切子命令」，status/log 也会写 .git/（G-X97）；贴 Doctor 终端的命令按 zsh 语义写——glob 多展开与命令替换不拆词双坑（G-X229）；交付命令块禁留尖括号占位符，贴块前逐行自问「原样粘贴能不能跑」（G-X134）；贴出的命令＝已启动的开关，贴后不得再穿插会改同一共享状态的操作（G-X106）；远端命令标清执行位置（fuxi 侧走 ssh fuxi-station，Mac 终端同名命令可能是别的工具）（G-X139）；Mac 上写的 Windows PowerShell 必须在 Windows 实跑一次再部署（EXP-20260917-001-T）。
2. **挂载层怪癖族**——挂载盘默认禁止删除，rm 报 Operation not permitted 走 allow_cowork_file_delete 一次申请会话内生效（G-X84）；挂载层跨进程读延迟会造 QA 假矛盾——批量 QA 一律同进程「加载→修→复检→写出」（G-X147）；Edit 报「File has been modified」可能是挂载盘 mtime 精度误报——先重读核实写入是否实落（G-X135）；批量回流/迁移会刷新 mtime——以 mtime 做排序/新鲜度判据的消费端系统性错排（G-X157）。
3. **路径纪律深化**——跨项目脚本回推根目录用「探测含标志子目录的祖先」替代硬编码 ../×N（G-X88）；派 subagent 的文件路径必须从权威数据源生成——凭标题编造的路径被静默兜底成「看似可用」（G-X175）。
4. **取数通道纪律**——通道验证必须用脚本同款通道——web_fetch 实测通 ≠ 脚本 urllib 通（G-X160）；通道状态会漂移——每班先验通道再取数（G-X128）。

## 五、自动化任务护航：从「哨兵与看门狗」到「自愈循环」

**v2.0 基线**：链路两半互设哨兵 · 看门狗三原则 · fail closed 防状态掩盖 · 确定性逻辑沉代码。
**v3.0 增量**：

1. **巡检自愈循环（2026-08-29 立）**——巡检定时任务自己也是个定时任务，它坏了谁发现？两层解法：第一层自证（读上次快照，>8 天则报「巡检中断过 N 天」）只在「有下一次跑」时才发得出声；第二层＝**定时的东西用不定时的东西兜底**（/resume 是唯一天然不定时、又必然会发生的检查点）。修复动作白名单化＋`_repair_audit.md` 留痕；白名单外 fail-closed 只报告；验收凭机器证据（lastRunAt/generated_at 前进且 triggered_by=scheduled，不凭自报）。
2. **调度班故障族**——调度班触发晚点同族三次→自愈覆盖＋晚点登记句（G-X224）；定时班的选择器不得用 glob/日期排序拾取治理资产——必须 exact pin＋非零拒绝（G-X162）。
3. **告警的信用管理**——告警的价值由它沉默的时候保证，一条误报就能让真信号从此没人看（G-X122）；告警三桶分级：known-noise 单列不定级——同时防假绿与假红（EXP-20260724-005-P）；关掉一个「会自我复发的告警」时必须同时留下为什么关（EXP-20260917-004-S）。
4. **指标的自指防护**——自检指标与它要检的对象同源 ⇒ 共模停更不可见（G-X193）；看板/卡片新鲜度按来源分层核——机器层的日更会掩盖同卡手工层的停更（G-X170）。
5. **部署即实证**——沙箱负向测试全绿 ≠ 真实环境首跑会过，部署类变更必须当天真实首跑（G-X178）；fixture 全链演练范式：复制真仓＋环境变量覆盖文档根＋真网演练去代理＋演练先于贴命令（EXP-20261013-001-T）。

## 六、上下文与知识工程：从「双轨」到「经验系统」

**v2.0 基线**：L0/L1/L2 分级加载 · GOTCHAS/经验库双轨＋难复得三问 · 引用先看状态行 · 做完即登记。
**v3.0 增量**：

1. **经验系统改造三件套（2026-09-03 起）**——① 薄索引 v2（10 字段含「触发条件」· 可重建 · 非事实源）；② 五阶段消费回执（retrieved→selected→encoded→consumer_verified→outcome_observed，只记实际证明到的阶段，可以停在中间）；③ 写侧根因条两判据：本场有落盘产物 ⇒ 留未闭等下游消费证据；无产物 ⇒ 终态行（否则未闭集合单调上升）。
2. **记忆冲突三向对读（brain-consolidate v1.3 · 2026-09-19 立）**——注入层（每轮在场、最危险）↔ 记忆正文 ↔ canonical 权威源；冲突分四级（一致/陈旧/对撞/同错）；结果由未参与实施的审核者 subagent 独立复核。
3. **damper 改动面纪律（2026-10-02 立）**——一句话判据＝本次修改的『真实改动面』是否等于『被点名的目标面』，超出即已在犯；十一族案例按需查用，不逐族叠加；按语义风险选零/一/两道审；结束时当场回灌实际新错。
4. **静默成功（G-X118）**——改动落进了真实存在、却没人读的位置；工具能写到哪，往往压过了任务该落到哪。
5. **状态与退役判据**——汇总/复盘的状态必须三分：「已提交」「源码已有分支」「运行验证通过」分开记，「未集成」≠「没有实现」（G-X172）；组件「停用/消失」≠ 该职能消失——架构换血期先找接班者再谈能力断没断（G-X210）；退役资产登记＝表×文件×函数三视角全查——少一个视角死资产就换个地方冒充现行（G-X133）；弃用三件套：停构建＋源码注释＋清元数据与监控注册——只做前两件死表会伪装成事故（G-X98）。
