# 备份策略

> 2026-05-14 初版（原名「Brain Vault 备份策略」，**只覆盖 `brain/`**）→ **2026-09-18 Doctor 补齐全域口径**。原版通篇无数据层，属结构性缺口：`brain/` 恰恰是有 git 远端兜底的那一半，真正需要备份设计的（不可再生的 DB／课件／raw）在原版里根本不出现。

## 总纲（2026-09-18 Doctor 定）

按「**文件类型 × 体积 × 重要性 × 成本**」分层，四个目的地各司其职：

| 目的地 | 承接什么 | 定位 | 成本 |
|---|---|---|---|
| **GitHub** | **一般文件**——repo 跟踪的文本／代码／文档／canonical JSON 等 | 日常备份 · 带版本史 · 任何机器 `git clone` 即恢复 | 免费 |
| **Fuxi-station** | **资源类大文件**——raw、视频、字幕、AIGC 等 | 日常备份 · 主力承接大件 | 局域网 |
| **TOS**（火山引擎对象存储） | **仅**「极重要 ＋ 小型 ＋ 需要冗余」的文件 | **二次冗余层**，不是主备份 | ⚠️ **有费用 → 范围严格限定** |
| **Time Machine** | 全机 | MAC 额外荣誉备份（兜底） | — |

**分工判据（按序问三句）**：① 丢了能不能再拿回来？（不可再生 → 进备份；可重下/可重拉的倒面清单见下）→ ② 多大？（大件走 fuxi；小件才考虑 TOS）→ ③ 多重要？（**只有「极重要的小件」才配占 TOS 的付费额度**——TOS 是冗余层，不是堆放场）。

**反面清单（明确不备份）**：可重下的（Douyin/YouTube 原始物料）· 可重拉的（`Market-Data` / Tushare 数据）· 本地回滚锚（`*.bak`）· **自身已有远端 git 的仓**（如 `Database/龙鱼-标的分析库` → 走自己的 `fuxi4ai/longyu-analysis-lib`）。

**fuxi 落点的目录性质（2026-09-18 核实 · Doctor 命题「Quarantine 不是隔离的意思么？」）**：
`F:\Mac_Quarantine\` **名实不符**——名字是「隔离区」，实则被当作「Mac 侧外移物落点」用，里面混装三类性质：**A 冷归档/备份（不可删）· B 批次备份 `todo-auto\`（不可删）· C 期满待删隔离件（有删除窗口）**。C 类历史上确已期满清除过（`_to_delete_20260721` 3.3GB 等，2026-08-22 前后）。**已补 `README.md` + `INDEX.md`**（逐件 SHA-256 实读 + 三类判读表 + 操作纪律：清理一律精确名单、**绝不用目录通配**；中文名按 ASCII 日期串匹配）。

## 实施

### 层①：GitHub（已就位）

仓库：`https://github.com/fuxi4ai/C.C..git`（私有）
分支：`main`
触发：每次 `/save` 走 **brain-save skill** 给命令 → Doctor 终端 `commit + push`（**不是**无人值守自动推）。

> ⚠️ **订正（2026-09-18）**：本条原文写「每次 `/save` 命令自动 `git add -A && git commit`」——**与 brain-save v2.9（2026-07-24 起）明令禁 `-A` 直接冲突**。禁令理由：工作树常积压本次范围外的未提交改动（别的会话／定时班遗留），`-A` 会一并混入、造成范围不明难回溯（G-X83 / DVA GOTCHAS GIT-20260723-001）。现行口径＝**先探后加**：`git status --short` 看清全部改动 → `git add <本次明确改动的文件列表>` → `git diff --cached --check` → commit。

**手动推送**（如果 /save 没推）：
```bash
cd ~/Documents/Claude/brain && git push
```

### 层②：本地 git（已就位）

`.git/` 目录内置版本历史。无需额外动作。

**恢复某次回退**：
```bash
cd ~/Documents/Claude/brain
git log --oneline           # 找目标 commit
git reset --hard <hash>     # 回到那个 commit
# 或保留当前改动只看历史：
git checkout <hash> -- <file>
```

### 层③：iCloud Drive 镜像

**方案 A · symlink 进 iCloud（推荐）**

把 brain/ 整体软链进 iCloud Drive，iCloud 自动同步：
```bash
cd ~/Library/Mobile\ Documents/com~apple~CloudDocs/
mkdir -p brain-mirror
ln -s ~/Documents/Claude/brain brain-mirror/brain
```
> ⚠️ iCloud 对软链的同步行为复杂，可能不可靠。优先用方案 B。

**方案 B · rsync 周期镜像（更可靠）**

跑 `~/Documents/Claude/brain/.tools/backup-icloud.sh`，每日 cron：
```bash
# crontab -e
0 3 * * *  bash ~/Documents/Claude/brain/.tools/backup-icloud.sh
```

## 恢复手册

### 全盘恢复（机器坏了）

```bash
mkdir -p ~/Documents/Claude
cd ~/Documents/Claude
git clone git@github.com:fuxi4ai/C.C..git brain
# 或：
git clone https://github.com/fuxi4ai/C.C..git brain
```

### 单文件误删

```bash
cd ~/Documents/Claude/brain
git log --all -- path/to/missing.md   # 找到被删的 commit
git checkout <hash>~1 -- path/to/missing.md
```

### iCloud 时光机

Finder → 进入 `~/Documents/Claude/brain/` → 顶部菜单"进入时间机器" → 选历史版本。

## 不进版本控制的内容

见 `.gitignore`：
- `.DS_Store`
- `.index/`（每次跑 build-backlinks 重新生成）
- `graphify/*/cache/`

## 监控

每周一手动跑：
```bash
cd ~/Documents/Claude/brain
git log --since='1 week ago' --oneline | wc -l   # 一周 commit 数
git remote show origin                            # 远程同步状态
ls -la ~/Library/Mobile\ Documents/com~apple~CloudDocs/brain-mirror/  # iCloud 最后同步
```

健康指标：
- 每周 commit ≥ 3 → ✓
- `git status` 显示 clean → ✓
- iCloud 镜像 mtime 在 24h 内 → ✓
