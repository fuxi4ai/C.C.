# 回切操作卡（PRD `2026-08-02_19班迁Kimi壳与三级司法` 交付物 A4/B4/F4）

> 用途：① 现在——切回 Cowork 时的**第一动作指引（disable 19 班）**；② 将来——若 Kimi 壳的班有更新、要回切 Cowork 做主，**文件覆盖即无缝衔接**的操作法。

## 一 · 几何现状（2026-08-02 迁移后）

| | Kimi 壳（主） | Cowork（备） |
|---|---|---|
| store 路径 | `~/Documents/Claude/Scheduled/` | `~/Claude's workspace/Scheduled/` |
| 班数 | **19（enabled，会 fire）** | 19（**待 disable**，见 §二） |
| prompt 真源 | 同一份（镜像逐字复制 + longyu 一条 F2 注记） | 同一份 |
| cron | 与 Cowork 注册表逐一相同（B3 已验 19/19） | 原值 |

**无缝衔接成立的前提（迁移时已锁定）**：① prompt 双壳通用（无壳专属硬编码）；② cron 两边一致；③ 文件结构同为 `{taskId}/SKILL.md`。⇒ 两 store 的全部差异 = 文件内容本身，**rsync 覆盖即完成切换**。

## 二 · 现在必做：Cowork 侧 disable 19 班（B4 · 双开防护）

> ⚠ 两壳只能单开，但「上午 Cowork、下午 Kimi」会让两边的班**同日双跑**（写同一批库）。所以切回 Cowork 的**第一动作 = 把 19 班全部 disable**（不删，留作可逆底牌）。

**操作（Cowork 侧，二选一）**：
- 侧栏 Scheduled 面板：19 个班逐个关 toggle；或
- 在 Cowork 会话里让那边的 CC 跑 `update_scheduled_task(enabled=false)` × 19，名单：
  `market-data-daily-update` `recap-kejian-daily-ingest` `refresh-risk-daily` `recap-kejian-review` `zhuzhao-market-fetch-daily-report` `cockpit-snapshot` `refresh-asset-dashboard` `us-close-backfill` `baize-breakout-sentinel` `event-attribution-watch` `baize-weekly-report` `agents-memory-meditation` `yuantu-alarm-weekly` `touzhijunjun-perspective-refresh` `longyu-weekly-dualscorer` `yuantu-alarm-earnings-season` `brain-monthly-checkup` `scheduler-weekly-audit` `repair-finance-chain`
- 核验：`list_scheduled_tasks` 19 班 `enabled` 全为 false。

⚠ 切回 Cowork 时若它先补跑了积压班（"closed→next launch 补跑"机制），别慌——补跑产物与 Kimi 侧同幂等（INSERT OR IGNORE/REPLACE 为主），但**同日双跑窗口越短越好，disable 先行**。

## 三 · 将来回切：Kimi store → Cowork store（⚠ 方向不可反）

> 场景：Kimi 壳用了段时间，班的 prompt 有更新（在 Kimi 侧 update_scheduled_task 改的），Doctor 决定回切 Cowork 做主。

```bash
# ⚠ 源 = Kimi store，目的 = Cowork store。反了会用旧文件毁掉新 prompt。
# 先 dry-run 看清单（-n 不实写）：
rsync -avn --delete \
  "/Users/lunarabbit/Documents/Claude/Scheduled/" \
  "/Users/lunarabbit/Claude's workspace/Scheduled/"
# 确认清单只有预期内的班（19 个 + 可能的 .bak），去掉 -n 实跑：
rsync -av --delete \
  "/Users/lunarabbit/Documents/Claude/Scheduled/" \
  "/Users/lunarabbit/Claude's workspace/Scheduled/"
```

- `--delete` 语义：Cowork store 里多出的班（Kimi 侧没有的）会被删——**实跑前核对 dry-run 清单**，若有想留的（如 `_archived/`），先搬走或加 `--exclude='_archived/'`。
- 回切后：Cowork 侧 `update_scheduled_task(enabled=true)` 恢复 19 班，Kimi 壳侧对应 disable（角色对调，同样防双跑）。
- artifacts 同理会已经在 Kimi 壳 store（`~/Documents/Claude/Artifacts/`）里更新——Cowork artifact 目录在 workspace 树，**artifact 的更新不走本卡**（update_artifact 是注册表操作，回切 Cowork 后由各班首跑自然刷回）。

## 四 · 字节级终封（B1 残余 · 迁移正确性的最后一道）

本壳 store 受应用保护（沙箱/CC 均不可读），19 班 prompt 的字节级核对只能在终端做：

```bash
cd ~/Documents/Claude
for d in brain/references/scheduled-live-mirror/live/*/; do
  t=$(basename "$d")
  [ "$t" = "_archived" ] || [ "$t" = "handshake-consumer-daily" ] && continue
  diff <(awk 'BEGIN{f=0}/^---$/{f++;next}f>=2' "$d/SKILL.md") \
       <(awk 'BEGIN{f=0}/^---$/{f++;next}f>=2' "Scheduled/$t/SKILL.md") >/dev/null \
    && echo "OK   $t" || echo "DIFF $t"
done
```

**预期**：18 行 `OK` + 1 行 `DIFF longyu-weekly-dualscorer`（唯一刻意偏离 = F2 口径切换注记，PRD §五 偏离 #1）。出现其它 DIFF = 迁建有变异，拿 diff 详情找 CC。

## 五 · F4 验证记录（2026-08-02）

- rsync 语法 dry-run 验证：沙箱内 `rsync -avn src/ dst/`（rsync 3.2.7）输出正常增量清单（DRY RUN 字样在）。
- 两侧 store 路径存在性：Glob 双侧各 19 个 `{taskId}/SKILL.md` 在（`~/Documents/Claude/Scheduled/` 与 `~/Claude's workspace/Scheduled/`）。
- 残余：真路径 dry-run 未跑（两 store 沙箱均不可达）——§三 的 dry-run 步骤即终验，Doctor 实跑前必走 -n。
