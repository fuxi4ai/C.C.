定时任务迁移工作流（方案 B）

通用工作流 · 以投知君君为例 · C.C. 目前理解版 · 2026-07-01 · 待讨论校准

核心一句话

方案 B 只做一件事：把定时任务里的重活（提炼）外包给 Codex；Claude 改为从握手层拿提炼结果 → 照原样写回该任务本来的库。
库、格式、写库动作、产出报告——全不变。 变的只有：提炼由谁做、数据从哪来。

二、握手层机制（通用交接管道）

  • 两个方向：to CC/scheduled/（Codex 写数据 payload）· to VV/scheduled/（Claude 写 ack 回执）；各留 latest + prev 两版。
  • consumer 流程（handshake-consumer-daily，每日 09:00）：扫 latest → 校验(schema + checksum + run_id 幂等) → 按 task_id 路由写库 → 写 ack → 报告 Doctor。
  • 幂等：每批唯一 run_id；比对 ack 里 last_consumed_run_id，相同则跳过、不重复写。
  • 规矩留 Claude 侧：数据真实性、不 promote、不在沙箱跑 git 写——Codex 只吐提炼数据，不越权落盘。

三、用投知君君走一遍（例子）

把上面的通用流程，代入投知君君这个具体任务：

① 原始语料：抖音视频 ASR 转写 → Database/Douyin/Transcripts/投知君君买方视角/*.transcript.txt（由 DVA-ops 脚本抓取+ASR 产出）
② 提炼（重活）：三分桶——产业规律 / 投资框架 / 剔除
③ 写自己的库：产业规律条目 → 行业研究/wiki/视角/投知君君/（_产业逻辑raw.md、_反共识纠偏录.md、图谱候选 PROPOSAL）
④ 迁移：②的提炼外包给 Codex → 写握手层 → Claude consumer 拿了照原样写回同一个渊图 wiki（格式、动作全不变）
边界（两条线的现状）：投知君君规划有两条线。上面举例的是 渊图视角层线（Claude 原来做的、本次迁移的对象）。另一条 DVA 金融提炼线目前尚未建立：DVA-ops 脚本现在只产出 transcript（＝ DVA 的原始语料），「提炼 transcript → 形成 DVA 报告 → 沉淀」这一步将来才做、现在还没做——不臆测。本次迁移只涉及渊图线。

四、迁移原则 + 当前状态

  • 逐个任务照搬：每个定时任务有自己的库，迁移时看它原来写什么库、就照原样写什么库——不搞统一体系、不复制新机制。
  • 投知君君是第一个试点，跑通后再逐个迁其余任务。
