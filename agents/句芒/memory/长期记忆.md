## 行情库维护经验（可复用做法）
- **给 `intl_index_daily` 加一条序列（2026-11-19 · SOX 首例）**：① 在 `烛照九阴/scripts/fetch_intl_index.py` 的 `INDICES` 加一行，kind 决定口径——`overnight` / `us_stock` 取数时丢掉当天没收完的那一根、存真收盘；`futures` / `macro_*` 存取数时点的快照。② **回补只针对新加的那一条**：引入脚本的 `fetch_yf` 单取，再单事务纯 `INSERT`。不能跑全清单 `--from`——写入是 `INSERT OR REPLACE`，会把快照类序列的历史读数整段覆盖。③ 写库照公共写锁协议（原子 `mkdir .market-data-writer.lock` + owner 文件，用完只放自己的锁），写前用 backup API 留 `_bak/market_data.db.bak_YYYY-MM-DD_<语义>`，提交前按 code 比行数与内容校验值、不过就回滚。④ 新序列先看星期分布，再和库里同市场的老序列对交易日集合，再拿第二处数据逐日对账。⑤ 同步查按 kind 取数的地方与 `ops/mac_us_close_backfill.py` 的验收清单 `US_LEG_CODES`——这份清单一共三处要对齐：脚本常量、`ops/README_launchd.md` 铁律第 5 条、Cowork 只读看门狗 SKILL 里手写的副本（后一处只能去 Cowork 侧改）。⑥ `MANIFEST.md` 手改口径注记，`MANIFEST.json` 只用 `Database/tools/build_manifest.py` 重跑生成。细节见 `logs/2026-11-19-SOX序列加入与回补.md`、烛照九阴 GOTCHAS `NOTE-20261119-001`。⑦（2026-11-23 美股五只复用）个股先拿雅虎 chart 的 meta（`longName` / `fullExchangeName` / `currency` / `firstTradeDate`）核身份和上市日，再对报告收盘；新上市的票首日 `pct_chg` 为空、历史不足 250 日要在 MANIFEST 写明；锁放掉时改名加后缀（如 `RELEASED-YYYYMMDD-mangmang-<语义>`），别撞上日更班的同名。见 `logs/2026-11-23-美股五只序列加入与回补.md`。
- **不取数、不写库地验编排器（2026-11-19 · 收盘班验收清单加 SOX）**：把编排器源码读成文本，用正则把库、日志目录、状态戳三处路径常量改到系统临时目录（每处断言恰好命中一次，没命中就拒跑，防止跑向真库），`exec` 装载后把 `run` 换成桩，再直接调 `verify()` / `main()`——现成范例是 `烛照九阴/tools/test_marketdata_staleness.py`。负例用 backup API 从只读连接造库副本再删行，同一副本上跑改前备份当对照。真库前后比 sha256 与修改时间。另记两班的分工：收盘班 `--from` 只从水位次日起、不回头补单条缺口；日更主班调外盘取数不带 `--from`、默认回看 12 天，缺口靠它补。细节见 `logs/2026-11-19-收盘班验收清单加SOX.md`。
- **沙箱里的小坑**：`lsof` 看不到别的进程，判断「有没有人在写库」要靠锁目录、库旁有无 `-journal` / `-wal`、再加 `BEGIN IMMEDIATE` 试锁；`diff <(…) <(…)` 这种写法在沙箱里报 `/dev/fd: Operation not permitted`，改成先落临时文件再比。

## 脱敏审查经验（可复用做法）
- **查「不泄密」别只扫整串，要做碎片拼合（2026-11-19 · 真相层第四轮复审首例）**：整串差分（源里候选值是否原样出现在抽取件）会漏掉「半遮掩」显示——同一枚令牌在一处露前 8 位、另一处露后 48 位，单看都不是完整凭证，拼起来就是全值。做法：先从源里挑出高置信凭证（各家前缀、带密钥键名的值、56 位 hex 等），再把抽取件所有 ≥10 位字母数字串建成集合，逐个凭证找它出现在抽取件里的最长子串，并把同一凭证的前缀碎片、后缀碎片合起来算覆盖率。打印一律只给形态（长度、字符类、熵），不给原值；含原值的中间件放 `$TMPDIR`，审完即删。
- **扫源目录先核覆盖面，rg 默认会静默跳过（2026-11-19 · 真相层第五轮复审）**：本机 `rg` 是 claude 二进制包的 shell 函数，默认不进隐藏目录、遵守 .gitignore——Cowork 会话都在 `…/.claude/projects/` 下，第一遍形态扫描源侧候选几乎为 0，差点当成「源里本来就没有」。做法：一律加 `--hidden --no-ignore`，先用 `rg --files … | wc -l` 对一遍预期文件数；Python 里调用要 `subprocess.run(["rg",…], executable=<claude 二进制路径>)`。凭证值只走内存：把碎片当模式经 stdin 喂给 `rg -z -F -f -`，不落模式文件。
- **审黑名单本身：键名启发式会把非凭证收进来**：`*_AUTH_HEADER=Authorization` 因键名含 auth 被收为「凭证」，结果全库的 Authorization（连 "National Defense Authorization Act"）都被遮。审已知凭证黑名单时，先按「形态 + 是否像占位/单词」把名单逐值过一遍（只打印形态），再做碎片差分。
- **高熵兜底的固定阈值对短串失效**：香农熵上限是 log2(长度)，阈值 4.3 时随机 24 位 base62 只能遮住约四成、28 位约七成七、32 位约九成四（实测各 2000 例）。审这类规则先跑「长度 × 捕获率」表，再谈够不够。
- **自写扫描器返回 0 条先查正则，不当「干净」（2026-11-20 · 真相层第六轮复审）**：在 Python 原始字符串里把 JSON 转义写成 `\\\\?`，正则就变成「必须有一个反斜杠」，键值扫描整批 0 命中，差点判成零残留；修成 `\\?` 后实际 763 条待分类。做法：每个自写模式先拿一条合成样例跑通、确认能命中，再上全库。
- **凭证原值不落盘，连中间件也不行（同轮）**：想把源里命中的原值 pickle 到 `$TMPDIR` 再离线分类，被自动模式拦了（敏感信息外泄）。改成同一进程内即时分类，只打印计数和形态（长度、字符类、熵、`aA9` 掩码），通过。
- **键值规则要专门试 Markdown 写法（同轮）**：`token: `值``、`API_KEY=`值``、`**Token**: 值`、`「值」`、`令牌（Tushare）：值` 都会绕过只认引号和冒号的规则；审脱敏时把这几种当成合成样例的固定项。
- **逐行读 jsonl 用 split("\n")，别用 splitlines（2026-11-20 · 真相层第七轮复审）**：`ensure_ascii=False` 写出的 JSON 行里可能有 U+2028 等字符，`str.splitlines()` 会在字符串中间断行，`json.loads` 报「Unterminated string」；`readlines()` 和 `split("\n")` 不受影响。
- **按工具名过滤会话记录时，Cowork 的 bash 叫 `mcp__workspace__bash`（同轮）**：只认 `Bash` 会漏掉 Cowork、Gateway、fuxi 三类来源里的大多数命令（本轮实数 6123 条）；文件读写工具名两边相同（Read/Write/Edit），Grep 另算。
