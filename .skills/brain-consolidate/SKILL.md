# brain-consolidate — brain 原生记忆固化

> 对 brain vault 做一次反思性整理：把成熟、反复出现的会话日志蒸馏成长期知识，去重、修时间引用、修剪索引。
> brain 的日志是**只增不减**的工作史（数百篇），本 skill 负责把其中"可复用的"沉淀进 `permanent/`，让未来 session 不必翻全部日志就能定位。

## 触发

- `/consolidate` / `/固化记忆`
- "固化记忆" / "整理记忆" / "记忆固化" / "蒸馏日志"

## ⛔ 三类门禁（最重要，不可绕过 · 2026-09-04 Doctor 立「经验治理闭环」）

本 skill 只**定义流程**，**绝不**在被加载时自动执行整理。因为它会动到大量既有笔记，是 brain 维护动作里唯一会**大面积改写历史**的，务必最谨慎。按操作类型走三类门禁：

1. **structural（结构性改动）**：先**只读盘点** → 提交**「拟改动 diff」清单**（改哪些文件、新增/归档/合并了什么）→ **等 Doctor 批准后才落盘**。大面积项（日志归档、巨型文件分片、格式统一）分批分场做。
2. **permanent（长期记忆候选）**：蒸馏进 `permanent/` 的长期记忆候选须经 **Doctor 质量确认**——批准 diff 即质量背书，不是只批流程；质量存疑的条目不得借 gotcha 通道夹带。
3. **gotcha（实错/坑登记）**：定位项目 canonical GOTCHAS 并**查重后直接登记**（GOTCHAS 自动登记合同），不受 permanent 门禁限制——consolidate 中发现实错，不得因「diff 未批」而不登记。

### Step 1.5 · 记忆冲突核查（只读 · **2026-09-19 Doctor 立** · 结果进 Step 2 清单）

> **为什么加这条**：2026-09-18/19 夜实撞——两份 README（canonical）**一直一致且正确**，而 `MEMORY.md` 的**索引行**把 skill 真源方向记反了。`MEMORY.md` 索引行是**每轮自动注入会话上下文**的那一层，README 只在主动去读时才进视野 ⇒ **对的那边要"记得去查"才出现，错的却天天在场**。这是 G-X151「旧文未替换」的**镜像**：那次是旧文还活着、新的没人看；这次是**错的活着、对的没人看**，且更隐蔽——注入行是"看不见的存在"，不会有人想到去核它。

**核对面（同一事实可能同时存在于三层，三向必须同口径）**：

| 层 | 位置 | 危险度 |
|---|---|---|
| ① **注入层** | `MEMORY.md` 索引行 · Settings 全局块 · `brain-anchors` 等常驻加载物 | 🔴 **最高**——每轮/每次触发就在场，错了无人察觉 |
| ② **记忆正文** | `memory/*.md` 正文 | 🟡 按需读 |
| ③ **权威源** | 该事实的 canonical：项目 `README` / `GOTCHAS` / 决策记录 / skill 正文 / 镜像文档 | 🟡 只在主动去读时进视野 |

**扫描顺序（先扫最危险的）**：①↔② → ②↔③ → ①↔③（三角闭合，缺一边即漏）。

**判据与处置（分级 · 不自行择一）**。**分级按「哪条腿冲突 + 能否判定」两个轴定**；为避免与上表「层危险度」的符号撞义，**本表不用 🔴🟡 符号、用文字级名**：

| 级 | 形态（含哪条腿） | 处置 |
|---|---|---|
| **一致** | 三向语义一致（表述差异可接受） | 不算冲突，不动 |
| **陈旧** | **有唯一一个落后方**，且另有权威源可判 | 列入 Step 2 diff「改落后方」 |
| **对撞** | 两处对同一事实给**互斥口径，且两边都有出处** | **不自行择一** → 单列「待 Doctor 裁」 |
| **同错** ⚠ | **①/② 彼此一致、却与 ③ 冲突**（或 ①↔③、②↔③ 任一腿） | **最危险形态**：两个「常用层」互相印证、只有少读的 canonical 是对的 → **优先级最高，逐条列出 ①②③ 三方原文**，不得只报两方 |

> **三条腿全覆盖**：①↔② / ②↔③ / ①↔③ **任一条腿**的冲突都按上表定级，**①↔③ 与 ②↔③ 同权**——不要因为 ③「平时不读」就降级。
> **本条的来源案例正是「同错」级**（2026-09-18/19 夜）：`MEMORY.md` 索引行（①）与记忆正文（②）**双双记反**、两份 README（③）是对的 ⇒ 是 **①② 同错 vs ③**，**不是**「①② 层之间冲突」。

**③ 层怎么定位（权威源判定程序 · 2026-09-19 复验后补）**：
1. 先看该事实有没有**明文声明的 canonical**（项目 `README`/`CLAUDE.md` 首注、`permanent/已装skill清单.md`、`references/凭证清单.md` 这类「注册表」文件常直接写）；

**第五类·通则适用范围核查（级名 `通则` · 2026-09-19 由 equity-thesis 案例立）**：一条通则（如「portable 是派生」）套到不属于它的成员上，会推出**错误结论**。核法：**通则必须带成员清单**；写成「所有 X / 一律 / 全部」而不附名单的散文式通则，**一律视为待核**，逐成员问「它真在这条通则里吗」。

## 边界 / 区别

- **vs 通用 consolidate-memory**:那个针对通用 `MEMORY.md` 模型,与 brain 的 `logs/permanent/inbox` 结构不符;brain 一律用本 skill。
- **vs brain-save**:brain-save 是单次会话**写入**(/save);brain-consolidate 是跨多篇日志的**回顾蒸馏**(/consolidate),频率低、动作重、需 Doctor 逐项批。
