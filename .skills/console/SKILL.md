# console — 中控台（目标和工作指派）

> 2026-11-10 Doctor 立。只装 Code 侧（派分支、收汇报依赖 Code 标签的会话工具，Cowork 里跑不了）。
> 中控台用本会话当前模型；分支默认同模型，Doctor 另有指定时从其指定。
> 同一个台同时只开一个中控会话（Doctor 2026-11-10 定）；不同的台可以同时开，见「多台并行」。

**路径基准**：本技能、索引、台账、迭代记录里的相对路径一律相对 `~/Documents/`（例：`Claude/brain/consoles/_index.md`、`Database/行业研究/追踪研究索引.md`、`AI4ME/渊图-outputs/`）。不写省略了 `Claude/` 的简写。

## 路由

| 输入 | 行为 |
|---|---|
| `/console`（无参数） | 读 `Claude/brain/consoles/_index.md` 取启用中的台，再逐个读其台账表头（`open_items`、`last_activity`），列出域、未结项数、上次活动日；用 AskUserQuestion 让 Doctor 选。索引里没有任何台时，说明可用 `/console new <域>` 新立，然后停止 |
| `/console <域>` | 在索引里按「域」或「别名」匹配，进入该台。匹配不到时列出已有的台并问是否新立，不猜、不自动建 |
| `/console new <域>` | 进入「新立一个台」流程 |
| 「开中控台」「进 AI 中控」等自然语言 | 能确定域就按 `/console <域>` 处理，否则按无参数处理 |

## 文件

| 文件 | 作用 |
|---|---|
| `Claude/brain/consoles/_index.md` | 各台的导航表，唯一登记处：域、别名、边界、路径、是否启用。只在新立或停用一个台时改。定位台账只从这里走，不凭记忆、不猜路径 |
| `Claude/brain/consoles/{域}/台账.md` | 该台的现状：目标、分支、持续更新文件及其消费端、待 Doctor 裁定或处理项。表头带 `open_items` 与 `last_activity` |
| `Claude/brain/consoles/{域}/迭代记录.md` | 该台的流水：每次派工、收报、裁定、文件更新各记一条，只追加 |

台账记现状，可改写；迭代记录记经过，只追加。两者冲突时以盘上实际文件和会话为准，并订正台账。

**未结项的数法**：`open_items` ＝ 台账「待 Doctor 裁定或处理」节的条数，现读现数，不含目标表与分支表。

## 进台流程

### 1. 定位与读入

1. 读 `_index.md`，取该台的台账与迭代记录路径。
2. 读台账全文；读迭代记录最后 30 条。
3. 按台账「领域背景」节列的指针读相关项目的 GOTCHAS 开放项（按 `Claude/brain/permanent/经验索引.md` 定向取，不整文件读）。指针指向的文件不存在时报出来并订正台账，不跳过。
4. 首次进台的会话先载全局协作偏好（`Claude/brain/permanent/全局偏好-Settings镜像.md`）；本会话已跑过 `/resume` 的不重复。

### 2. 对账

台账是上次写下的说法，不是现状。逐项对一遍：

- **分支**：用会话列表工具取本会话派出的分支（`list_sessions`，`linked: true`，并带 `include_archived: true`；默认只返回 20 条且不含已归档，分支多时调大 `limit`）。台账里登记、但不是本会话派出的分支，按其会话 id 用 `get_session` 查。查到后比对最近活动时间与台账所记状态：台账写已收尾而之后又有活动的，标出并去看它做了什么。确实查不到的才写「查不到」。
- **持续更新文件**：逐个核文件是否还在登记路径、最近修改时间；路径失效的标出，不猜新路径。
- **待提交**：对台账涉及的仓跑只读 `git --no-optional-locks -c core.quotepath=off status --short`，列出与本台相关的未提交文件，分清已暂存与未暂存。

### 3. 报现状表

一张表报给 Doctor，每行注明「核过」或「台账所记、未核」：

- 未结目标及其进度
- 分支：在跑／待 Doctor 裁／待验收／已结
- 持续更新文件：上次更新日、是否到期
- 待 Doctor 裁定项（给推荐与理由）
- 待 Doctor 终端处理的提交

报完即等 Doctor 给目标，不自行开工。

## 指派

- Doctor 在中控台给出的目标，属本台领域的，直接拆题开分支，不再逐次问在哪做。几下工具调用能答完的问题在中控台直接答，不开分支。
- 每个分支的简报写清：目标、范围与涉及文件、完成的样子、证据要求（金融数字与外部事实标「实跑／实读／推断／未核」）、哪些事要回报中控台而不自行决定（方向性选择、超出简报范围的改动、提交）。简报用自己的话写全，不写「见上文」。
- 默认开本地分支。云端分支不会回报，除非 Doctor 明说要云端。
- 会写同一批文件的分支不并行，排队执行；只读的分支可以并行。
- 检索顺序、信源分级、数据真实性等项目规矩不因走分支而放松，简报里点到与该题相关的条目。
- 派出即记台账与迭代记录（见「自行更新」）。

## 多台并行

不同的台可以同时开。各台的台账与迭代记录互不相干；索引平时不写。会相撞的是跨台共用的资产：

- **跨台共用的数据资产**（渊图主库、追踪研究索引、行情库等）：派一个要写这类文件的分支之前，先读索引里其他启用中的台的台账，看其分支表有没有在跑的分支登记了同一文件。有则排队，并告诉 Doctor 在等哪个台的哪个分支；本台派出时在分支表「涉及写入」栏登记该文件，供别的台查。
- **`TODO.md`、`通用教训.md`、各项目 GOTCHAS**：写前读盘，只改局部。
- **提交**：给 Doctor 的命令只列本台归属确定的文件，不带别的台的改动。

## 收报

- 分支每结束一轮，系统会通知本会话，不定时轮询。
- 分支的汇报是它的说法，不是证据。转述给 Doctor 前，对关键结论做回读（产出文件是否存在、改动范围是否与其所述一致）；没核的明写「照录、未核」。
- 验收照签字分轨：事实性的开未参与实施的审核者核验后落签；方向性的问 Doctor，给推荐与理由。派工的中控台不算「未参与实施」时（例如简报里已给出结论），另开审核者。
- 分支提出超范围改动或方向性选择时，中控台不代 Doctor 答，转给 Doctor。
- 提交与推送交 Doctor 终端；中控台汇总各分支的待提交文件，逐文件列出，只列归属确定的。

## 自行更新（常驻授权，不提醒、不请示）

下列三样，凡发生派工、收报、Doctor 裁定、持续更新文件被改、分支结束或归档，当即更新，不问 Doctor：

| 文件 | 更新内容 |
|---|---|
| `台账.md` | 目标与分支的状态、产出路径、待裁项的增删、持续更新文件的上次更新日、消费端登记的增补；表头 `open_items`、`last_activity` |
| `迭代记录.md` | 追加一条：日期、事件类型（派工／收报／裁定／更新／订正）、内容一两句、证据或路径、核验状态。同日多条按发生先后排 |
| `_index.md` | 仅在新立或停用一个台、改别名或边界时 |

写的规矩：

- 写前先读盘上现文，用 Edit 改局部，不整文件重写；并发会话可能也在写。
- 改正文的同一轮把表头 `updated:` 改为当日。
- 日期一律 `YYYY-MM-DD`；计数现读现数。
- 只记已发生的事。分支还没回报的结果不预写。
- 本授权只覆盖这三样的事务性维护。持续更新文件本身（追踪研究、政策追踪稿等）按其自己的格式标准和确认规则更新；其中判断性内容仍走原有确认。

每轮结束时，回报里用一行说明这三样改了什么，不展开。

## 消费端同步提醒

台账「持续更新文件」表给每个文件登记消费端：哪个程序、定时班或文档在读它，以及同步用的命令。

- 某个持续更新文件被改（中控台或分支改的都算），当轮回报里点名其消费端，写明需要做什么、命令是什么、由谁跑。
- 只提醒并给命令，不代跑；消费端自己有 skill 的（如 `/update`）指到那个 skill。
- 发现新的消费关系，当即补进台账该表。
- 消费端一栏为空不等于没有消费端：登记时写「未查」或「已查、无」，两者分开。

## 新立一个台

1. 查 `_index.md` 确认没有同域或近义的台；有则进既有的台，不重复立。
2. 问 Doctor 三件事（能从上下文确定的不问）：领域边界、已有的持续更新文件、相关项目。
3. 建 `Claude/brain/consoles/{域}/台账.md` 与 `迭代记录.md`（结构照既有的台），在 `_index.md` 登记一行。
4. 持续更新文件逐个查消费端后再登记。

## 离台

- Doctor 说「退出中控」「收台」，或转去做与本台无关的事时：把台账写到当前实况，迭代记录补齐，报一句未结项数。
- `/save` 时，日志里写本台路径与当日迭代记录的起止，不重抄台账内容。

## 边界

- 不为定位台账去全盘搜索；索引里没有的台就是没有。
- 不在中控台直接做本该派给分支的长活；也不为几下能答完的事开分支。
- 不推看板、不建定时班（归 Cowork 侧）。
- 不替分支宣称通过；不把分支的汇报当已核事实写进台账，台账里照录的内容标「分支所报」。
- 台账与迭代记录是工作记录，不是长期记忆；值得长记的仍走 `/save` 的记忆分拣。
