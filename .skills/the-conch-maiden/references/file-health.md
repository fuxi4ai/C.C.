## 第 3 步 · 每类问题怎么处理（路由表）

| 问题类型 | 处理手段 | 执行细则 |
|---|---|---|
| 陈旧件、版本链超额（确认过期、无人引用） | **归档**：移入 `archived/`，可回滚 | `archive.md` 第 3 步 |
| 该归档但引擎不判陈旧的单件（如已执行的一次性补丁） | **手工归档**：移入 `archived/`，在迭代记录与日志留痕 | `archive.md`「手工归档单个文件」 |
| 同一文件多版本并存、逐轮复核稿、散落快照 | **整理·合并归一**：合成一份现行件，文首落迭代记录，再删旧版 | `tidy.md` 规则 1 |
| 已完成的委托、知会、申请、请求、交付说明 | **整理·删除**（有用的一两句并入结果件迭代记录）；被别的文档当「规格」「依据」引用的照办 | `tidy.md` 规则 2 |
| 回测目录 | **整理·回测分诊**：有引用的保留，被取代的删除，有历史意义的移入 `archive/` | `tidy.md` 规则 3 |
| 命名违规（含存量） | **整理·改名**并跟改引用；存量件列为候选，改不改在第 5 步问 | `tidy.md` 规则 4 |
| 按时间追加的过程记录式文档、标题版本号落后于正文 | **整理·版本理顺**：对齐版本标注，篇头加「现行条文一览」，正文不动 | `tidy.md` 规则 5 |
| 改名或归档要改生产代码里写死的文件名 | 列出要改的代码行；何时做、怎么做在第 5 步问，代码改动按该项目自己的流程 | SKILL.md 原则「不得降级」一条 |
| 被定时班正文或项目外消费者点名的接口文件名不合规 | 列出点名它的对侧与班；改名须对侧同步（通用纪律第 6 条），改不改在第 5 步问 | 同上 |
| 未提交的代码改动、未跟踪的唯一副本、已忽略却仍被跟踪的件 | 不改文件：给 Doctor 逐文件的提交命令；后者用 `git rm --cached`，盘上保留 | SKILL.md 通用纪律第 9 条 |
| 断链、过期路径、过期状态注、入口清单缺漏、无人挂账的待办队列 | **文档订正**（改前备份到同目录 `_bak/`；冻结件不改，在所属 README 记一句）；待办队列只挂账到 brain `TODO.md`，裁定归 Doctor | 本文件审查清单 H |
| 嵌套层、放错上级、边界外的研究 | **迁移** | `migrate.md` |
| 不再使用的项目、目录、文档、软链接 | **退出**：删本地靠远端留底 / 进回收站 / 移入 brain 快照 / 删链接 | `retire.md` |
| manifest 策展值失准、状态行未同步、缺标准文件 | **确认档优化动作**（`manifest_fix`、`gotchas_status_sync`、`fill_workfiles`） | `health.md` 第 3 步 |
| 在用的项目或库不在 manifest 里 | **新增清单节点**（手工，先备份） | `health.md` 第 3.5 步 |
| 看板与 manifest 需要刷新 | **`rescan`**（先备份 manifest，再 survey 与重建看板）；只为刷新一个节点的分数不跑 | `health.md` 第 1 步「只为刷新某一个节点的分数」一条 |
| 任何删除 | **回收站** | `recycle-bin.md` |
| 引擎误判、工具非预期行为 | 不处理文件，登记海螺 GOTCHAS | SKILL.md 通用纪律第 10 条 |

删还是归档：`tidy.md` 规则 1、2 原定的处置是删旧版、删沟通件，2026-11-18 的批语是「标注且归档」。本版没有改默认动作，逐次在第 5 步问，汇报里把两种做法都写上。

细则按清单里实际命中的手段读，用不到的不读（1.5.0「每次只读用到的那份细则」的 2.0 读法）。

一个对象可能同时命中几类（如旧回测既是版本链超额又是回测目录）：按路由表从上到下取最贴切的一种，汇报里写明为什么选它。
