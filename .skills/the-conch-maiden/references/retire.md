# conch · 处理手段：退出（文件健康审查及整理 · 1.5.0 起）

> 2026-11-17 首例：Financial 清理——GlobalPercent 本地副本删除（靠 GitHub 留底）、创新药科技轮动与备查区进回收站、`协作架构与开发需求_20260610` 移入 brain 作历史快照、`Financial/README.md` 按现状重写。
> 2.0.0 起退出是「文件健康审查及整理」的处理手段之一（总则 `file-health.md` 审查清单 E）；下方第 1 步交 Doctor 的判定并入七步第 5 步。方向性问题同样在第 5 步、子代理复查之后问。
> 适用：判断一个项目、目录或文档是否还在用，并把不用的退出。目标目录定法与禁区同 SKILL.md 第 1 步。

## 第 1 步 · 判定还有没有用（只读）

每个对象列一行：最近修改时间、git 末次提交、有没有定时班或 launchd 在跑它、有没有消费方（按 `references/migrate.md` 第 1 步三种写法扫）、有没有 brain 档案、是不是别处的软链接或副本。线索不是结论；结论用 AskUserQuestion 交 Doctor，每个对象给推荐处置与理由：

| 处置 | 适用 |
|---|---|
| 删本地，靠远端留底 | 有 git 远端且已同步。删前实测本地分支、`origin/<分支>`、`git ls-remote origin <分支>` 三者同一个提交，工作树干净；把恢复命令（`git clone <远端>`）写进 brain 决策记录 |
| 进回收站 | 没有远端或远端不全、已确认不再使用的；按 `references/recycle-bin.md` |
| 移入 brain 作历史快照 | 有参考价值的文档：放 `brain/references/`，文首加「已过时」说明与现行入口指针 |
| 删软链接 | 链到别处真身的入口；只删链接，真身不动，删前 `readlink` 确认指向 |
| 保留 | 仍有消费方或在跑 |

## 第 2 步 · 执行

1. 快照；查近 2 小时并发写入。
2. 有归档回执、审计记录这类留档的，先移到 brain 对应项目目录，再处置本体。
3. 停用件（`.plist.disabled` 等）随本体处置，删前确认 `launchctl list` 里没有它。
4. 按处置执行；回收站件先挪本机暂存，两端 SHA 一致后才删本机。

## 第 3 步 · 收尾

- 上级目录的 README（如 `Financial/README.md`）按现状重写：只列在用的项目（职能、负责方、入口指针），另列「已退出」一节写去向。旧版备份到同目录 `_bak/`。负责方查不到就写「见其 README」，不猜。所有指针逐个确认存在。草稿先过子代理复查再给 Doctor 看 diff（SKILL.md 第 6 步「重写稿先复查」，2.2.0）。
- `brain/permanent/项目总览.md`、项目 stub 与决策记录各写一条；经验索引按需重建。
- 独立核验：子代理逐件确认处置落实、指针不断、远端留底可用。
- commit 与 push 交 Doctor 终端。

## 不做

- 不在没有实测远端同步的情况下删本地。
- 不删真身来处理软链接。
- 不替 Doctor 定「还有没有用」；判定不明的保留。
