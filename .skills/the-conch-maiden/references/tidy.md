**五条规则**（前四条是 Doctor 2026-11-17 的要求；规则 5 与规则 2、4 里标 2.4.0 的两段是 2026-11-18 加的，起因见 SKILL.md 版本说明）
1. **多版本合并归一**：同一文件并存的 `-v1`、`-v1.1`、`_bak` 快照、逐轮复核稿，合并为一份现行件（活文档去掉版本号与日期，版本写 frontmatter）。现行件文首落「## 迭代记录」：版本表（版本·日期·作者·变化要点）＋「旧版中已删除、仍有参考价值的内容」（被推翻的结论写推翻理由）＋复核摘要。迭代记录是旧版信息的唯一留存，写完才删旧版。
2. **已完成的沟通件直接删除**：委托、知会、申请、请求、交付说明等。删前把仍有用的一两句（委托范围、知会的落地结果）并入对应结果件的迭代记录；引用处改为纯文本说明。被交付清单、manifest 或代码引用的「交付包」不是沟通件，不删。（2.4.0）被别的文档引用不是把已办完的请求稿留在原处的理由：先核请求稿里有没有至今在用、别处没有的内容（字段定义、阈值、裁定原话），并入结果件，引用改成指向结果件或纯文字，再处理请求稿（风险日报首例：两份请求稿因被《机制扳机词表》引用，只改了状态注）。
3. **回测分诊**：被调度、现行 PRD、消费方、门禁工具或主库版本引用的保留；被新版取代的旧结果删除；不再复用但有历史意义的移入 `archive/`。**引用要跨项目查**（brain `.tools/`、其他项目、调度镜像）——只查本项目会漏（EAL 首例：`backtest/repro_v23` 在 EAL 内 0 引用，实被 brain `eal_gate_check.py` 按路径读取）。
4. **命名按项目既有范式统一**：读项目 README 的命名规定；`.conchconfig.yml` 设 `date_style: suffix`（主题-YYYY-MM-DD）或 `prefix`（YYYY-MM-DD-主题）。脚本、`backtest/`、`raw/` 内文件默认豁免（脚本靠目录名定位）。（2.4.1）存量不合规的文件名不自动改名：列进清单，经 Doctor 同意后改，并同时修被引用和消费处；不以登记「既成例外」代替列出（Doctor 2026-11-18 的原话见 SKILL.md 原则「不得降级」一条）。原名里的日期保留；上面的默认豁免与冻结证据不动。改名后跟改全部现行引用（除完整路径串外，另按路径段扫代码里 `os.path.join` / `Path` 分段拼接的写法，并对被调度执行的脚本逐个解析路径常量、确认存在；目录层级变化时另扫 `parents[N]`、`.parent.parent` 与 `../` 相对链接——GOTCHA-20261117-001 两条追记）；日志、迭代记录等只追加的账本不改旧条，另追加一条改名对照。
5. **版本理顺**（2.4.0，风险日报三份提案首例）：按时间追加的过程记录式文档，后面的节会改掉前面的写法，标题版本号常落后于正文。只动篇头：标题版本号、版本清单与正文对齐（各版对应哪些节用 `git --no-optional-locks show <提交>:<文件> | grep '^## '` 核，补编的版本号写明是补编的）；加一张「现行条文一览」（事项｜以哪一节为准｜已作废或被取代），只指路不立新规，每一行都往后查更晚的节有没有再改它；正文各节不动，改完与入库版自第一个编号节起逐字节比对。入口页与 brain 待办里的版本、节号提法同步改，会话日志不改。要不要另出一份只含现行条文的稿子、过程稿怎么处置，在第 5 步问。

**流程**
1. 预演：`cd "$TMPDIR" && python3 -B ~/Documents/Claude/Projects/海螺姑娘/conch_engine.py --scope "<目标>" tidy-scan`（`--json` 出机器可读）。只读，报五类线索：版本族、散落备份、沟通件、项目内无引用的回测目录、命名违规。线索不是结论。
2. 逐件核查后列**处置清单**交 Doctor：合并（现行件←旧版）、删除、迁出、归档、改名，每件写理由与引用处理。方向性问题（研究边界、命名取向、删除方式）先用 AskUserQuestion 问。
3. Doctor 确认清单后执行：
   - 动手前本机快照（tar.gz 放项目数据根或 `brain/backups/`）；查近 2 小时有无并发写入，共管账本只做定点插入。
   - 待删件先**挪进本机暂存** `<数据根>/backups/_to_delete_YYYYMMDD/`，同时写 `MANIFEST.tsv`（类别·原路径·SHA-256·字节）。挪动可逆，打包上 fuxi 前不删任何东西。
   - 合并类等迭代记录写完、核过再挪旧版。冻结研究包（结果里记了脚本 SHA 的）迁移时保持相对结构，不改脚本。
   - 跟改引用；跑项目自带校验；迭代记录 / 工作日志各追加一条（含改名对照与删除清单指针）。
4. **回收站**：按 `references/recycle-bin.md` 执行（fuxi-station，保留 ≥15×24 小时，精确名单清理）。
5. 独立核验：开未参与实施的 subagent 实读复核（清单逐件落实、引用无断链、迭代记录覆盖旧版要点、校验通过）。

**不做**：不自动合并（引擎不判断新版是否取代旧版）；不跳过清单确认；不在 Codex Project Mirror 内执行；不改冻结研究包脚本；不改 GOTCHAS 状态。
